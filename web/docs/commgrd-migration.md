# CommGrd 이행 기록 (2026-09-06)

화면이 직접 쓰던 `DxGrid` 를 공통 그리드 `CommGrd` 로 옮긴 작업의 기록이다.
**자율 진행분이라, 판단이 필요했던 것과 아직 눈으로 못 본 것을 아래에 적어 둔다.**

## 무엇을 했나

두 갈래를 옮겼다.

| | |
|---|---:|
| `DxGrid` 를 직접 쓰던 표 → `CommGrd` | 53개 (화면 42개) |
| `CrudGrid` 를 쓰던 화면 → `CommGrd`, 그리고 `CrudGrid` 삭제 | 12개 |
| **지금 `CommGrd` 를 쓰는 표** | **64개 / 53파일** |

`DxGrid` 쪽은 기계적 치환이다 — `<DxGrid` 를 `<CommGrd TItem="…"` 으로,
`</DxGrid>` 를 `</CommGrd>` 로 바꿨고 나머지 파라미터는 손대지 않았다.
`CommGrd` 가 선언하지 않은 것을 전부 그대로 넘기기(splat) 때문이다.

남은 `<DxGrid` 는 셋뿐이다 — `CommGrd` 자신과 `AutoGrid` · `DynamicGrid`.

빌드 통과 · 아키텍처 테스트 **86건 통과**.

### 함께 고친 것

| 무엇 | 왜 |
|---|---|
| `CommGrd` 에 `DetailRowTemplate` 추가 | 네 화면이 쓰고 있었다 (InquiryList · ArchiveListPage · BillingStat · PlayerDownload) |
| 안 쓰는 표에서 펼침 칸 억제 | 템플릿을 늘 선언해야 해서, `DetailRowDisplayMode`·`DetailExpandButtonDisplayMode` 를 `Never` 로 눌러 둔다 |
| `SelectedDataItemChanged` 에 형 명시 | splat 되는 값은 Razor 가 형을 몰라 메서드 그룹을 못 넘긴다. `@@((object? item) => …)` 로 바꿨다 (PortalCommonCode · DeviceList) |

## `CrudGrid` 는 없앴다

12개 화면을 `CommGrd` 로 옮기고 부품을 지웠다. 슬롯 이름만 갈아 끼우면 되는
일이었다 — 나머지 파라미터는 이름과 뜻이 같다.

| CrudGrid | CommGrd |
|---|---|
| `<ChildContent>` | `<Toolbar>` |
| `<EditForm>` | `<EditFormTemplate>` |
| `<Columns>` · `EditFormTitle` · `OnNew` · `OnSave` · `OnDelete` · `Reload` · `ExportName` | 그대로 |

**단추 자리가 바뀐다.** `CrudGrid` 는 표 **위**에 등록·엑셀·조회를 두었는데
`CommGrd` 는 표 **아래 띠**에 아이콘으로 둔다. 열두 화면이 함께 그렇게 된다.

**남은 일** — 이 화면들의 조회 조건이 아직 `<Toolbar>`(표 위)에 있다.
새 구성은 조건을 `CommSch` 로 올리는 것이다. 기계적으로 옮길 수 없어
(조건마다 라벨을 붙여야 한다) 화면을 손댈 때 하나씩 옮기는 편이 맞다.

## 일부러 안 옮긴 것 — **확인이 필요하다**

### 1. 모듈 전용 부품 둘 (`AutoGrid` · `DynamicGrid`)

화면이 아니라 **부품**이고, 각자 `DxGrid` 를 감싸고 있다.

| 부품 | 쓰는 화면 | 하는 일 |
|---|---:|---|
| `AutoGrid` (헬프데스크) | 37 | 서버가 준 칸을 그대로 그린다 |
| `DynamicGrid` (프로젝트관리) | 24 | 프로시저 메타로 칸을 만든다 |

**둘을 `CommGrd` 위에 얹으면 61개 화면이 한꺼번에 바뀐다.** 파일 두 개만
고치면 되는 대신, 잘못되면 61개가 같이 잘못된다. 그래서 판단을 남겼다.

### 2. `TItem` 을 못 정한 넷

`Data=` 식에서 항목 타입을 추정했는데 넷은 못 찾아 `object` 로 두었다.
읽기 전용 표라 동작에는 지장이 없다(`TItem` 은 편집 흐름에서만 쓰인다).
나중에 그 화면을 손댈 때 제 타입으로 바꾸면 된다.

## 이행으로 **달라지는 것** — 화면을 열어 봐야 안다

`CommGrd` 는 감싸기만 하지 않고 기본값을 준다. 53개 표가 다음을 함께 얻었다.

| | 이전(화면마다 달랐다) | 지금 |
|---|---|---|
| 순번 칸 | 없음 | **맨 왼쪽에 `No`** |
| 쪽 나누기 | 화면마다 20 · 25 · 50 … | **15건** |
| 아래 띠 | 없음 | **등록 · 다시 읽기 · 칸별검색 · 엑셀** 아이콘 |
| 줄 선택 | 화면마다 달랐다 | 눌러서 한 줄 선택 |
| 글자 줄바꿈 | 켬 | **끔** (칸이 좁아도 줄이 안 늘어난다) |

**대시보드 안의 작은 표에는 과할 수 있다.** 아래 화면들이 그런 자리다 —
열어 보고 어색하면 그 표에서 `ShowRowNumber="false"` · `ShowFooter="false"` 로
끄면 된다.

- `PushDashboard` (추세 · 사유) · `HelpDeskDashboard` (최근 요청)
- `ServerStatus` 넷 (서비스 · AI 제공자 · 컨테이너 · 이미지)
- `WeatherForecast` (시간대) · `WeatherHistory` (시간별)
- `MyInfoPage` (설정) · `Profile` (활동 기록)
- `DeployStatus` (실행 · 러너) · `ReleaseNotes` (대상 · 실행)

좌우 분할 화면(`PortalCommonCode` · `CompanyUserList`)의 **왼쪽 목록**도
아래 띠가 붙는다. 거기서는 엑셀이 어색할 수 있다.

## 기본값은 **화면에서 다시 적지 않는다**

칸별검색(`ShowFilterRow`)은 **숨김이 기본**이다. 필요하면 표 아래 띠의 깔때기
아이콘으로 켠다. 그런데 이행 직후 37개 화면이 `ShowFilterRow="false"` 를 들고
있었다 — 옛 `DxGrid` 시절에 적어 둔 것이 그대로 딸려 온 것이다.

그대로 두면 **기본값을 바꿔도 그 화면들만 안 따라온다.** 게다가 무엇이 기본값
이고 무엇이 그 화면의 뜻인지 읽어서 구분할 수 없다. 그래서 전부 걷어냈다.

| 지운 것 | 건수 |
|---|---:|
| `ShowFilterRow="false"` · `="true"` | 37 |
| `ShowSearchBox="false"` · `PageSize="15"` · `SelectionMode` 등 | 26 |
| `DetailExpandButtonDisplayMode="…Auto"` (템플릿이 있으면 CommGrd 가 정한다) | 4 |

**기본값과 다른 값은 얼마든지 적어도 된다** — 그것이 그 화면의 뜻이다.
같은 값만 막는다. `CommGrdDefaultTests` 가 검사하는데, 기본값을 손으로 옮겨
적지 않고 `CommGrd.razor` 에서 읽어 오므로 기본값을 고치면 검사도 따라온다.

## 표의 기본 생김새 — 브라우저에서 재어 정했다

네 가지를 기본값으로 넣었다. **전부 떠 있는 화면에서 계산값을 읽어 확인했다.**

| | 어떻게 |
|---|---|
| 고른 줄이 **진한 강조색** | `FocusedRowEnabled="true"` |
| 짝수 줄 **줄무늬** | `CustomizeElement` 로 클래스, 색은 `app.css` |
| 칸 머리 글자 **가운데** | `app.css` (자료 칸은 안 건드린다) |
| 조회 조건 라벨이 칸 **왼쪽** | `CommSch` 기본. `Stacked="true"` 면 위로 |

### 선택색은 원래도 테마를 따르고 있었다

「테마를 안 따른다」로 보이던 것의 정체는 **너무 옅은 것**이었다. 선택만 켜면
`--dxbl-grid-selection-bg` 가 걸리는데 Fluent 파랑에서 `#e7eff9` 다 — 흰 바탕과
3% 차이라 골랐는지 안 골랐는지 눈에 안 띈다. 강조 줄(`FocusedRowEnabled`)까지
켜면 DevExpress 가 `--dxbl-grid-selection-focus-dark-bg` 를 칠한다.

강조색을 바꿔 가며 잰 값이다 — 둘 다 테마에서 온다.

| 강조색 | 선택만 | 선택 + 강조 줄 |
|---|---|---|
| Fluent Blue | `#e7eff9` | **`#0b5699`** (흰 글자) |
| Fluent Rose | `#fde9eb` | **`#a0003e`** (흰 글자) |

줄무늬 색은 고정색이 아니라 글자색을 4% 섞어 만든다. 어두운 테마에서도
「한 톤 차이」가 되고, 그 옅기가 선택색을 이기지 않는다.

## 아직 눈으로 확인 못 한 것

브라우저 자동화가 DevExpress 단추 클릭에서 잘 안 먹어(회로가 끊긴 탭을 재는
일이 반복됐다) 아래는 **직접 봐 주셔야 한다.** DOM 으로 확인한 것은 ✓ 다.

| | 상태 |
|---|---|
| 순번 칸이 그려진다 / 그 칸에 필터 입력이 없다 | ✓ DOM 확인 |
| 화면 진입 시 조회하지 않는다 (`조회를 누르면 목록을 읽습니다`) | ✓ DOM 확인 |
| 아래 띠 아이콘 넷 · 화면 안에 보인다 · 쪽 스크롤 없음 | ✓ DOM 확인 |
| **조회** 를 눌러 목록이 실제로 채워지는가 | ✓ 확인 |
| **순번 값**이 1,2,3… 이고 쪽을 넘겨도 이어지는가 | ✓ 확인 — **버그였다**(아래) |
| **등록** 팝업이 열리는가 | ✓ 확인 — **버그였다**(아래) |
| **선택 행 색**이 DevExpress 테마를 따르는가 | ✓ 확인 — 옅어서 안 보였을 뿐 |
| 칸 머리 **세 번 클릭 → 정렬 해제** | ✓ 확인 — **버그였다**(아래) |

### 눈으로 보고서야 나온 것 셋

**셋 다 빌드도 테스트도 통과하던 것들이다.** 화면을 열어 재기 전에는 알 수 없었다.

| 무엇이 | 왜 |
|---|---|
| 2쪽 순번이 16 이 아니라 **31** 로 시작 | `VisibleIndex` 가 쪽 안의 자리인 줄 알고 앞 쪽 건수를 또 더했다. 실제로는 **전체 기준**이다 |
| 칸 머리를 세 번 눌러도 정렬이 **안 풀림** | 정렬은 `DxGrid` 안에서 끝나 부모가 다시 그려지지 않는다 — `OnAfterRender` 에 둔 코드가 **한 번도 안 돌았다.** `LayoutAutoSaving` 으로 옮겼다 |
| **등록 팝업이 말없이 안 열림** | 팝업 안 편집기의 검증 식은 **순수한 멤버 접근**이어야 한다. 형변환(`(IEnumerable<string>)a.RoleIds`)이나 메서드 호출(`ToDate(...)`)을 넣으면 거절당하는데, 화면에는 아무 표시도 없고 브라우저 콘솔에만 남는다 |

마지막 것은 `AccountDto` 에 형이 맞는 창(`Roles` · `BirthDateTime`)을 내어
`@bind-` 한 줄로 되돌렸다. **다른 화면에서 팝업이 안 열리면 이것부터 의심한다.**

## 되돌리는 법

이행은 커밋 하나로 묶여 있지 않다. 되돌리려면 `git diff` 에서
`<CommGrd TItem=` → `<DxGrid`, `</CommGrd>` → `</DxGrid>` 로 되돌리면 되고,
`CommGrd` 자체는 그대로 두어도 아무 화면도 그것을 쓰지 않게 된다.
