완료된 작업

  • 운영서버 환경 점검 — nginx · systemd · DB · 포트 전수 확인
  • GoldbApi 서비스 제거 + 배포물 삭제 (goldenbar 종료)
  • nginx 설정을 도메인별 10개 파일로 분리 (백업 보관)

확정된 방향

  • 백엔드는 Docker Compose로 운영이미지 태그로 배포·롤백, GHCR 레지스트리 사용
  • 1차 백엔드 범위는 최소 구성 6종Gateway · Auth · File · Site · Notify · Life — funeralv2Api · ProjMng · AIAgent · HelpDesk는 후속 확장
  • 저장소 확정: github.com/quristyle/Funeralv2public · 기본 브랜치 main — main push가 배포 트리거
  • 배포 방식: 서버에 self-hosted 러너 설치GHCR pull · compose up 담당 — SSH 키를 GitHub에 두지 않음
  • 프론트 2개는 컨테이너 없이 nginx 정적 서빙jsini-site (vite-ssg) · jsini-portal (SPA)
  • DB 준비 작업 없음 — 이미 작업 완료배포 단계에서 DB는 건드리지 않음
  • 기존 헬프데스크는 현행 유지이 저장소의 HelpDeskServer로 대체되는 시점에 컨테이너로 편입
  • nginx · RabbitMQ · DB · 인증서는 네이티브 유지

배포 흐름

git push (main)→ Actions: 이미지 빌드→ GHCR push→ 서버: pull · up -d
백엔드 롤백 = 이전 이미지 태그로 up · 프론트는 빌드 산출물을 nginx 루트에 교체
jsini.co.kr → jsini-site (정적)  ·  portal.jsini.co.kr → jsini-portal (SPA + 게이트웨이)
