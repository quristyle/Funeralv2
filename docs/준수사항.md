# JSini 관리 포털 — 준수사항

이 문서는 **이 저장소에서 작업할 때 반드시 지켜야 하는 규칙**을 모은 곳이다.
새 규칙이 생기면 아래 목록에 번호를 이어 추가한다.

- 규칙은 **번호를 바꾸지 않는다.** 없어진 규칙은 지우지 말고 `폐기` 로 표시한다
  (대화에서 "3번 규칙" 처럼 번호로 부르기 때문이다).
- 각 규칙은 **무엇을 · 왜 · 어떻게 확인하는가** 를 함께 적는다.
  '왜' 가 없으면 나중에 예외를 판단할 수 없다.
- 이 문서는 저장소 루트의 [`CLAUDE.md`](../CLAUDE.md) 가 가리키고 있어
  작업 시작 시 자동으로 읽힌다.

## 3. 모든 팝업은 헤더를 잡고 옮길 수 있어야 한다

### 무엇을

화면에 뜨는 모달(팝업) 창은 **헤더(제목 줄)를 마우스로 잡아 끌면 움직여야** 한다.

### 왜

팝업이 화면 가운데 고정되면 그 뒤의 내용을 확인할 수 없다.
공지 팝업을 띄운 채 목록을 보거나, 등록 창을 열어 둔 채 옆의 값을 확인하는 일이 잦다.

### 어떻게

**개별 화면에서 따로 처리하지 않는다.** 두 경로로 한 번에 걸어 두었다.

| 팝업 종류 | 처리 |
|---|---|
| vben 모달 (`useVbenModal`) | `modal-api.ts` 의 기본값 `draggable: true`. 부품이 이미 드래그를 지원한다 |
| ant-design-vue `<Modal>` | `plugins/draggable-modal.ts` 가 앱 시작 시 한 번 걸린다. DOM 을 지켜보다 `.ant-modal-header` 를 손잡이로 만든다 |

새 팝업을 만들 때 **추가로 할 일은 없다.** 다만 아래는 지킨다.

- 팝업에는 **제목(헤더)을 둔다.** 헤더가 없으면 잡을 곳이 없다.
  (`:title="null"` 로 헤더를 지우는 대신, 제목을 비워도 헤더 영역은 남긴다.)
- 헤더 안에 버튼을 넣을 때는 그 버튼에 `data-no-drag` 를 붙인다. 드래그가 눌림을 가로채지 않는다.

### 예외

- **Drawer(서랍)** 는 화면 가장자리에 붙는 부품이라 대상이 아니다.
- **전체 화면(fullscreen) 상태** 의 모달은 옮길 곳이 없으므로 드래그를 끄고, 해제하면 다시 켠다.

### 확인

팝업을 열고 제목 줄을 잡아 끌었을 때 창이 따라오면 된다.
닫았다 다시 열면 원래 자리로 돌아와야 한다.

## 4. 세로 스크롤 없이 한 화면에 담는 것을 지향한다

### 무엇을

화면(라우트 하나)은 **브라우저 세로 스크롤 없이** 보이는 것을 목표로 한다.
목록·표처럼 내용이 길어지는 것은 **그 부품 안에서만** 스크롤한다.

**이 규칙은 데스크톱(≥768px) 한정이다** (2026-08-30, 40번 문서).
모바일은 세로가 짧아 이 규칙을 우기면 그리드가 수십 px 로 압착됐다 —
모바일에서는 `.page-fill-last` 가 풀리고(styles/index.css) 페이지 세로 스크롤을 허용한다.
화면 코드는 그대로 두면 된다. 양쪽을 프레임워크·전역 CSS 가 알아서 가른다.

### 왜

세로로 길어지면 조회 조건과 결과가 한눈에 안 들어와서, 스크롤을 오르내리며 일하게 된다.
이 시스템은 조회·확인이 대부분이라 그 왕복이 곧 작업 시간이다.

### 어떻게

- 화면 최상단은 `<Page auto-content-height>` 를 쓴다. 내용 영역 높이가 정해져야
  안쪽 부품이 `height: 100%` 로 자리를 잡을 수 있다.
- **"조회 조건 줄 + 목록" 구조라면 `content-class="page-fill-last"` 를 함께 준다.**

  ```vue
  <Page auto-content-height content-class="page-fill-last">
    <SearchBar />      <!-- 자기 높이만큼 -->
    <Grid class="h-full" />  <!-- 남은 높이를 채운다 -->
  </Page>
  ```

  이걸 빼면 목록이 `h-full` 로 **영역 전체 높이**를 차지해서, 조회 조건 줄 높이만큼
  넘친다. 그러면 **내용 영역이 통째로 스크롤되어 조회 조건 줄이 위로 밀려 나간다** —
  조건을 보면서 결과를 보는 것이 이 시스템의 기본 동작이라 그게 제일 불편하다.
  클래스는 `src/styles/index.css` 에 있다.

  > 2026-08-23 레이아웃 개편 뒤에도 이 클래스는 **그대로 필요하다.** 직접 재 봤다 —
  > 부서 관리는 켜면 넘침 0, 끄면 79px. 프로젝트 참여자는 0 대 87px 이다.

  > **대시보드처럼 카드를 위아래로 쌓는 화면에는 쓰지 않는다.** 마지막 카드만 늘어나
  > 오히려 더 넘친다(고객사 현황에서 확인).

- 목록은 그리드 자체 스크롤(`height: 'auto'` + 그리드 내부 스크롤)을 쓴다.
  화면 전체를 늘려 페이지 스크롤을 만들지 않는다.
- 좌우로 나눌 수 있으면 나눈다(`SplitPane`). 위아래로 쌓으면 금방 넘친다.
- 팝업 본문이 길면 팝업 안에서 스크롤한다(`max-h-[52vh] overflow-y-auto`).

### 주의 — 높이가 정해지지 않으면 부품이 접힌다

`height: 100%` 는 부모 높이가 정해져 있어야 풀린다.
부모가 flex 계산으로 높이를 얻은 경우 백분율이 풀리지 않아, 고유 높이가 없는 부품
(Monaco 편집기 등)은 0 에 가깝게 접힌다. 그런 자리는 `absolute inset-0` 으로 채우거나
최소 높이를 함께 준다. (실제로 겪은 사례 — `components/code-editor/code-editor.vue` 주석 참고)

### 확인

1280×800 창에서 화면을 열고, **레이아웃 스크롤 컨테이너**의 `scrollHeight` 가
`clientHeight` 보다 크지 않으면 된다.

> 이 시스템은 문서 전체가 스크롤되지 않는다(레이아웃이 내용 영역만 스크롤한다).
> 그래서 `document.documentElement` 를 재면 항상 0 이 나온다 — **스크롤 컨테이너를 재야 한다.**

```js
const el = document.querySelector('#__vben_layout_scroll');
el.scrollHeight - el.clientHeight;  // 0 이어야 한다
```

> **2026-08-23 에 재는 곳이 바뀌었다.** 예전에는 `.h-full.p-4` 를 쟀는데,
> vben 상위의 레이아웃 스크롤 개편을 들여오면서 내용 영역 클래스가
> `min-h-0 flex-1 overflow-y-auto p-4` 로 바뀌었다. `auto-content-height` 를 쓰지 않는
> 화면은 이제 `.h-full` 을 갖지 않아 예전 선택자로는 **아무것도 못 잡는다.**
> 경위는 [17-vben-upstream-sync.md](analysis/17-vben-upstream-sync.md) 6.7 참고.

**측정할 때 주의.** 자료가 늦게 들어오는 화면이 많아 화면을 연 직후에 재면 0 이 나온다.
3초쯤 기다린 뒤 두 번 재서 큰 값을 쓴다. (이 함정 때문에 한 번은 '고쳤다'고 잘못 판단했다.)

### 예외 — 길어도 되는 화면

대시보드·리포트처럼 **원래 길게 훑어보는 화면**은 이 규칙의 대상이 아니다.
억지로 한 화면에 우겨넣으면 글씨와 차트가 읽을 수 없게 작아진다.
어떤 화면이 예외인지는 [`docs/analysis/16-준수사항-점검.md`](analysis/16-준수사항-점검.md) 에 정리했다.

### 예외 — 회사 소개 사이트 (`fronts/apps/jsini-site`)

이 규칙은 **업무 화면의 규칙이다.** 조회 조건과 결과를 한눈에 두는 것이 목적이고,
그 목적은 로그인해서 일하는 화면에만 있다.

회사 소개 사이트는 대상이 아니다. 처음 온 사람에게 순서대로 읽히는 것이 목적이고,
거기서는 **스크롤이 서술 수단**이다. 한 화면에 우겨넣으면 읽는 순서가 사라진다.

`fronts/apps/jsini-site` 는 `@vben/*` 를 쓰지 않으므로 `<Page auto-content-height>` ·
`page-fill-last` 도 해당되지 않는다. 배경은
[`docs/analysis/27-jsini-site-brand.md`](analysis/27-jsini-site-brand.md) 2절에 있다.

## 5. 글꼴은 저장소 안의 파일만 쓴다

### 무엇을

화면 글꼴은 **저장소에 넣어 둔 파일**로만 불러온다. 바깥(Google Fonts·CDN)에서 받지 않는다.
순서는 **S-CoreDream → Play → 기존 시스템 글꼴**이다.

### 왜

인터넷이 닿지 않는 내부망에서 돌아가는 시스템이다.
바깥에서 받게 두면 그 망에서는 요청이 실패하고 글꼴이 기본값으로 떨어져,
같은 화면이 장비마다 다르게 보인다.

### 어떻게

- 파일: `apps/jsini-portal/public/fonts/` — 조건과 출처는 그 폴더의 `README.md` 에 있다
- 선언: `src/styles/fonts.css` (`@font-face`)
- **순서는 `src/styles/font.ts` 한 곳에서만 정한다.** 두 곳이 그 값을 가져다 쓴다.

  | 쓰는 곳 | 왜 필요한가 |
  |---|---|
  | CSS 변수 `--font-family` (`app.vue` 가 넣는다) | body 와 우리가 만든 화면 |
  | antd 테마 토큰 `fontFamily` (`app.vue`) | **antd 가 만들어 내는 규칙** |

  > antd 는 CSS-in-JS 로 거의 모든 컴포넌트에 자기 `font-family` 를 넣는다.
  > CSS 변수만 바꾸면 antd 컴포넌트는 antd 기본 글꼴로 남는다 —
  > 실제로 화면 요소 26,000개가 그랬다. vxe-table 도 자기 변수(`--vxe-ui-font-family`)를 쓴다.

- 사용자는 **환경설정 › 테마 › 기본 글꼴**에서 바꿀 수 있다(기본값 S-CoreDream).
  고른 값은 열쇠이고 실제 글꼴 목록은 `font.ts` 가 정한다.

새 글꼴이 필요하면 **파일을 받아 넣고 `fonts.css` 에 선언한 뒤 `font.ts` 에 묶음을 추가한다.**
`<link href="https://fonts.googleapis.com/...">` 같은 바깥 주소를 넣지 않는다.

### 확인

화면을 열고 개발자 도구 네트워크에서 `fonts.googleapis.com` · `gstatic` · `jsdelivr` 로 나가는
요청이 하나도 없으면 된다. 글꼴은 `/fonts/...` 로만 받아야 한다.

```js
document.fonts.check('16px S-CoreDream');  // true
getComputedStyle(document.body).fontFamily; // S-CoreDream, Play, ...
```

> Play 는 라틴 전용이고 S-CoreDream 이 라틴 글자도 갖고 있어, 평소에는 내려받히지 않는다.
> S-CoreDream 에 없는 글자가 나올 때만 쓰인다 — 정상이다.

## 6. 표는 `useVbenVxeGrid` 하나로만 그린다

### 무엇을

목록·표를 그릴 때는 `#/adapter/vxe-table` 의 **`useVbenVxeGrid`** 를 쓴다.
ant-design-vue 의 `<Table>`, `vxe-table` 의 `<VxeTable>` 을 직접 쓰지 않는다.

**정렬과 필터를 화면에 적지 않는다.** 공통 레이어가 이름줄 정렬과 필터 전용 행을
자동으로 붙인다. `sorter` · `filters` · `filterMethod` · `filterRender` ·
깔때기 토글을 새로 쓰는 것은 이 규칙 위반이다.

**엑셀 내려받기 · 재조회 · 필터 초기화 단추도 따로 만들지 않는다.**
그리드 아래 도구줄이 자동으로 붙는다(페이저가 있으면 페이저 줄 왼쪽,
없으면 표 아래 줄 왼쪽). 화면에 같은 단추를 또 두면 두 벌이 된다.

### 왜

같은 목적의 구현이 네 벌까지 갈라졌던 적이 있다(2026-08-30 이전).
화면마다 정렬·필터를 따로 적으면 동작이 조금씩 달라지고, 표에 기능을 하나 더할 때마다
화면 100개를 찾아다녀야 한다. 한 곳에 모아 두면 거기만 고치면 된다.

### 어떻게

```ts
const [Grid, gridApi] = useVbenVxeGrid({
  gridOptions: {
    columns: [{ field: 'name', title: '이름', minWidth: 140 }],
    height: 'auto',
    pagerConfig: { enabled: false },          // 전량 조회면 반드시 적는다
    proxyConfig: { ajax: { query: async () => await fetchList() } },
  },
});
```

- `:table-data` 로 자료를 넣는 그리드는 재조회 방법을 모른다. 아이콘이 나오게 하려면
  `gridFeatures: { onRefresh: () => 불러오기() }` 를 준다.
- **그리드 위에 무언가(도구 줄 등)를 두면 `<Grid class="h-auto min-h-0 flex-1">` 로 준다.**
  프레임워크가 붙이는 `h-full` 을 그대로 두면 그 높이만큼 넘치고, vxe 가 다시 재면서
  **표가 몇 번에 걸쳐 길어진다**(41번 문서 3.5). 그리드가 그 영역의 유일한 자식이면
  아무것도 안 줘도 된다.
- 안 맞는 칸만 끈다 — 컬럼에 `params: { filter: false, sort: false }`.
- 값이 정해진 칸은 `params: { filterOptions: [{ label, value }] }` 를 준다.
  고르는 칸이 되고, **엑셀 필터처럼 여러 개를 고를 수 있다**(하나라도 맞으면 남는다).
- 화면에 보이는 글자와 저장된 값이 다르면 `params: { filterText: (row) => string }`.
- 그리드 전체를 끄려면 `gridOptions.gridFeatures: { filter: false }`.

자세한 것은 [`adapter/vxe-grid-features.ts`](../fronts/apps/jsini-portal/src/adapter/vxe-grid-features.ts)
머리말과 [41번 문서](analysis/41-grid-unification.md) 에 있다.

### 예외

- 표가 아니라 **배치(layout)** 용도로 쓰는 `<table>` — 그리드가 할 일이 아니다.
- `/system/menu` 는 아직 자기 머리글을 쓴다. 정렬·필터가 걸리면 자리 이동을 막아야
  해서다(34번 문서). 공통 레이어가 필터 상태를 알려 주게 되면 옮긴다.
- **회사 사용자 관리의 소속 · 미소속 표** — 행을 끌어다 옮기는 장치라 antd 로 남겼다.
  vxe 에는 행 엘리먼트에 드래그를 붙일 자리가 없다(41번 문서 6.3).

### 확인

```bash
grep -rn "ant-design-vue" --include=*.vue fronts/apps/jsini-portal/src/views | grep "Table"
```

걸리는 것이 없어야 한다. 화면을 열었을 때 머리글이 두 줄(이름줄 + 필터줄)이면 된다.
