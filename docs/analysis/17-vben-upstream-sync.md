## 1. 먼저 — 우리는 어디서 갈라졌나

저장소에 상위 원본 정보가 남아 있지 않아 **파일 내용으로 분기점을 찾았다.**

우리 트리의 프레임워크 파일 400개를 골라 해시를 내고, 상위 저장소의 커밋을 거슬러
올라가며 몇 개가 일치하는지 셌다. 일치 수가 가장 높은 지점이 분기점이다.

```
분기점   4a16040d3  2026-04-10  "chore: update deps"   (400개 중 280개 일치)
상위 HEAD e3369bd63  2026-08-19
그 사이   커밋 384개 (packages·internal 만 보면 242개 — fix 114, feat 50, refactor 11)
버전      양쪽 다 5.7.0 (상위는 5.7.0 안에서 계속 고치고 있다)
```

280/400 만 일치하는 이유는 **우리가 이미 많이 손댔기 때문**이다. 주석을 한국어로 바꾸고,
드래그 가능한 모달·글꼴·Page 높이 등을 고쳐 두었다. 이게 이번 작업의 난이도 대부분이다.

파일을 네 갈래로 나눠 보면 이렇다.

| 갈래 | 수 | 뜻 |
|---|---|---|
| 양쪽 다 그대로 | 372 | 할 일 없음 |
| **상위만 바뀜** | 227 | 그대로 가져와도 안전한 후보 |
| **양쪽 다 바뀜** | 119 | 3-way 병합이 필요 |
| 우리만 바뀜 | 160 | 우리 커스터마이즈 — 건드리지 않는다 |
| 상위 신규 파일 | 86 | 새 기능/새 컴포넌트 |

### D-U2. form-ui 전면 재작성 — 가져올까 🔴

상위는 7월에 폼 엔진을 **`@tanstack/vue-form` + zod v4** 로 다시 썼다
(`28757fb9c`, `98dea9222`, `9f5b1cd9f` 등). 새 파일만 `form-runtime.ts`, `form-codec.ts`,
`field-name.ts`, `rule-registry.ts`, `deprecation.ts` … 그리고 테스트 12개가 생겼다.

여기에 딸린 버그 수정이 10건 넘게 있는데(배열 필드 포커스 유지, 슬롯 props, zod4 배열 처리 등)
**엔진을 안 옮기면 하나도 못 가져온다.** 조각만 넣었다가 타입이 깨져 되돌린 게 이번에 2건 있었다.

**의견: 지금은 넘기는 게 낫습니다.** 우리 화면의 폼은 잘 돌고 있고, 이 교체는 D-U1(zod4)과
한 몸입니다. 다음 큰 정비 때 D-U1 과 묶어서 하시죠.

### 6.6 🟠 결정이 필요한 것 — `componentProps` 타입 표

상위는 컴포넌트마다 실제 props 타입을 적은 표(`ComponentPropsMap`)를 두고
스키마의 `componentProps` 를 자동 완성·검증한다. **우리는 그 표를 느슨하게 뒀다.**

```ts
// apps/jsini-portal/src/adapter/form.ts
export type ComponentPropsMap = Record<ComponentType, Record<string, any>>;
```

정확한 표로 바꾸면 오타를 미리 잡을 수 있다. 대신 **폼 스키마 100여 곳을 다시 봐야 한다** —
우리 화면은 antd 컴포넌트를 감싸 쓰는 자리가 많아 그 표와 어긋나는 곳이 꽤 나올 것이다.
(우리 포크가 예전에 이 기능을 걷어냈던 것도 같은 이유로 보인다.)

| | 방법 | 비고 |
|---|---|---|
| **A** | 지금처럼 느슨하게 둔다 | 기존 화면 그대로. 자동 완성은 없다 |
| B | 자주 쓰는 컴포넌트만 좁힌다 (Input·Select·DatePicker …) | 점진적. 화면을 조금씩 손보면 된다 |
| C | 상위처럼 전부 적는다 | 가장 안전하지만 화면 100여 곳 재검증 |

**의견: B 를 권합니다.** 새 화면을 만들 때 이득이 크고, 기존 화면은 건드리지 않아도 됩니다.

### 6.7 🟡 곁들여 딸려 온 것 — 레이아웃 스크롤 개편(D-U3)

1차에서 "별도 작업으로 잡아 달라"고 적었던 **D-U3 가 이번 전체 동기화에 함께 들어왔다.**

무엇이 바뀌었나 — **내용 영역이 스스로 스크롤한다.**

```

후:  레이아웃에 전용 스크롤 컨테이너(#__vben_layout_scroll)가 생기고
     내용 영역이 `min-h-0 flex-1 overflow-y-auto p-4` 로 자기 안에서 스크롤한다

`auto-content-height` 를 안 쓰는 화면은 그 클래스를 갖지 않는다.
새 기준은 `#__vben_layout_scroll` 이다. **[`docs/준수사항.md`](../준수사항.md) 4번을 그에 맞게 고쳤다.**

### 6.10 🟡 남은 잡음 — vxe-table 경고

```

우리 스키마에서 쓰는 횟수 기준 상위권이다(Input 95, Select 25, InputNumber 15, Switch 13 …).
나머지는 그대로 느슨하다.

```ts
export type ComponentPropsMap = NarrowedComponentProps &
  Record<Exclude<ComponentType, keyof NarrowedComponentProps>, Record<string, any>>;
```

> 처음엔 `Record<ComponentType, ...> & { Input: InputProps }` 로 썼는데,
> 교집합의 `any` 인덱스가 이겨서 **좁혀지지 않았다.** 위처럼 "좁힌 것"과
> "나머지"를 나눠야 실제로 좁혀진다. 타입 수준 단언으로 확인했다.

**기존 화면은 하나도 안 깨졌다** — 타입 오류 26개 파일 그대로.

**얻는 것과 못 얻는 것을 정확히 적어 둔다.** 상위 form-ui 는 `componentProps` 를
`P & Record<string, any>` 로 두기 때문에, 좁혀도 **잘못된 값에서 오류가 나지는 않는다.**
얻는 것은 **편집기 자동 완성**이다 — `component: 'Input'` 인 스키마에서 `componentProps: {` 를
치면 antd Input 의 props 가 뜬다. 오타를 줄이는 데는 그것으로 충분하다.

새 컴포넌트를 좁히려면 `NarrowedComponentProps` 에 한 줄 추가하면 된다.

### 6.13 6.7 진행 결과 (레이아웃 스크롤 개편 마무리)

세 가지를 정리했다.

1. **측정 기준을 `#__vben_layout_scroll` 로 바꿨다.** [`docs/준수사항.md`](../준수사항.md) 4번의
   확인 방법을 고쳤고, 왜 바뀌었는지도 적어 뒀다.
2. **`page-fill-last` 는 계속 필요하다.** 개편으로 걷어낼 수 있나 싶어 직접 재 봤다 —
   내용 영역이 `overflow-y-auto` 가 되면서, 클래스를 빼면 **내용 영역이 통째로 스크롤되어
   조회 조건 줄이 위로 밀려 나간다.**

   | 화면 | 켰을 때 | 껐을 때 |
   |---|---|---|
   | 부서 관리 | 넘침 0 | 79px |
   | 프로젝트 참여자 | 넘침 0 | 87px |

   33개 화면에 그대로 둔다.
3. **전 화면 재측정.** 198개 중 194개 측정, 169개가 넘침 40px 이하.
   40px 초과 25개는 전부 16-준수사항-점검.md 의 R1~R4 로 이미 기록된 화면이다.

### 6.11 한국어 문구가 되돌아간 곳 — 전수 확인해서 복구

병합에서 상위 코드를 받으면 **우리가 번역해 둔 한국어 문구도 함께 되돌아간다.**
자동 복원은 '한 줄 전체가 주석인 것' 만 잡아서, 나머지를 따로 훑었다.

방법: 동기화 전 파일과 지금 파일을 비교해
**"한글이 있던 줄이 사라지고 그 자리에 중국어가 들어온"** 파일을 전부 찾았다.

| 파일 | 무엇이 되돌아갔나 |
|---|---|
| `common-ui/.../workbench-header.vue` | **화면에 보이는 문구** — 할 일 · 프로젝트 · 팀 → 待办 · 项目 · 团队 |
| `form-ui/src/types.ts` | 코드 끝 주석 6곳 |
| `form-ui/src/use-form-context.ts` | 코드 끝 주석 3곳 |
| `shared/src/cache/__tests__/storage-manager.test.ts` | 코드 끝 주석 11곳 |
| `vite-config/src/plugins/archiver.ts` | 코드 끝 주석 1곳 |

전부 한국어로 되돌렸다. 새로 들어온 배열 필드 컴포넌트(`form-field-array.vue`)의
기본 문구(操作 · 添加一行 · 暂无数据)도 한국어로 바꿨다.

> **다음에 동기화할 때도 이 확인을 빼먹지 말자.** 코드 끝에 붙은 주석과
> 템플릿 안의 문구는 자동 복원이 못 잡는다.

### 6.11 되돌리는 법

의존성까지 바뀌었으니 파일만 되돌리면 안 된다. **셋을 함께** 되돌려야 한다.

```bash
git checkout -- fronts/packages fronts/internal fronts/apps fronts/package.json fronts/pnpm-workspace.yaml fronts/pnpm-lock.yaml
cd fronts && pnpm install --frozen-lockfile
```

동기화 직전 상태를 tar 로도 떠 뒀다(세션 임시 폴더). 필요하면 말씀해 주시면 꺼내 드린다.
