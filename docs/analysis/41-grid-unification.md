> 지시: "프론트에는 많은 화면에서 테이블형태의 그리드를 사용하고 있다.

> "필터를 보여주는 row 가 별도로 보여지도록 해야 됨을 잊지마라."

작업일: 2026-08-30

## 1. 시작할 때의 상태 — 표를 그리는 방식이 셋이었다

| 방식 | 화면 수 | 어디 | 정렬·필터 |
|---|---|---|---|
| `useVbenVxeGrid` | 38 | 포털 · 장례식장 · 생활과환경 | 4개 화면만, 제각각 |
| ant-design-vue `<Table>` | 37 | **헬프데스크 19** · 포털 10 · 기타 8 | 거의 없음 |
| `projmng/shared/dynamic-grid.vue` (raw vxe) | 21 | 프로젝트관리 전부 | 전 컬럼 있음(깔때기 팝업) |

같은 목적의 구현이 **네 벌** 있었다 — 계정 관리(깔때기 팝업), 메뉴 관리(머리글 아래 입력칸),
`RoleUserTab`(antd 2줄 머리글 + 손으로 짠 필터), `DynamicGrid`(깔때기 토글).
화면이 늘 때마다 다섯 번째가 생기는 구조였다.

## 2. 공통 지점은 새로 만들지 않았다 — 이미 있었다

그리드를 쓰는 화면은 **예외 없이** `#/adapter/vxe-table` 의 `useVbenVxeGrid` 를 거친다.
39개 파일을 다 뒤졌고 한 곳도 우회하지 않았다. 그래서 새 `<JsiniGrid>` 를 만들어
화면마다 갈아끼우는 대신, **그 함수 안에서 컬럼을 손보는 방식**을 택했다.

```
adapter/vxe-table.ts
   useVbenVxeGrid()
     ├ adjustGridForMobile()   모바일 보정 (40번 문서, 이미 있던 것)
     └ createGridFeatures()    정렬 · 필터 전용 행  ← 이번에 추가
```

**화면 코드는 한 줄도 안 바뀐다.** 기존 38개 화면이 그대로 새 머리글을 갖는다.

`fronts/packages` (vben 포크)에는 넣지 않았다. 거기에 우리 기능을 쌓을수록
상위 동기화 비용이 커진다(CLAUDE.md).

## 3. 머리글은 **진짜 두 줄**이다

```
┌──────────┬──────────┬──────────┐
│ 사용자명 ▲│ 소속 회사│ 상태     │  ← 1행: 이름. 누르면 정렬
├──────────┼──────────┼──────────┤
│ [검색   ]│ [검색   ]│ [전체 ▾]│  ← 2행: 필터만
├──────────┴──────────┴──────────┤
```

처음에는 머리글 칸 **안에** 이름과 입력칸을 쌓았다. 보기에는 비슷하지만
"필터 행이 따로 보여야 한다" 는 요구를 못 채운다 — 두 줄 사이에 선이 없어서
필터가 하나의 띠로 읽히지 않는다.

그래서 컬럼을 묶음으로 바꿔 **표의 행을 실제로 둘로** 만들었다.

```
{ field:'userName', title:'사용자명' }
  → { title:'사용자명', children:[ { field:'userName', title:'' } ] }
```

필터를 안 다는 칸(작업 버튼 등)은 묶지 않는다. 안 묶인 칸은 vxe 가 두 줄을 합쳐
그리므로(rowspan) 줄이 어긋나지 않는다.

**정렬은 1행이 맡는다.** 화살표가 필터줄에 끼면 입력칸과 뒤엉키기 때문이다.
vxe 의 정렬 자체는 그대로 쓰고(아래 칸의 `sortable`), 이름줄 클릭이 `grid.sort()` 를
부른다. `sortConfig.trigger` 기본값이 '화살표를 눌렀을 때' 라, 필터줄의 화살표를
감추면 그 줄을 눌러도 정렬되지 않는다.

**필터의 조건과 판정은 vxe 것을 그대로 쓴다**(`filters` · `filterMethod`).
필터줄은 `setFilter()` 로 값을 넣어 줄 뿐이다 — 걸러내는 규칙을 두 벌로 만들면
언젠가 둘이 어긋난다. (34번 문서에서 이미 세운 원칙이다.)

머리글 높이는 계정 관리 기준 **80px** 이다(한 줄일 때 40px). 준수사항 4번은
지켜진다 — 확인한 화면 전부 `scrollHeight - clientHeight = 0` 이었다.

## 3.5 그리드 아래 도구줄 (2026-08-30 추가)

> 추가 지시: "그리드의 공통으로 하단 왼쪽에 엑셀 export · 재조회 · 필터 초기화를
> 아이콘으로 제공해 줘. 페이지네비게이션 영역이 보이는 경우에는 그 왼쪽 부분에.
> 결론적으로 페이지네이션이 존재하든 안 하든 그리드 아래에 영역이 존재하고,
> 왼쪽 부분에는 공통 아이콘이 보이도록 한다."

```
┌────────────────────────────────────────────┐
│ … 표 …                                     │
├────────────────────────────────────────────┤
│ 📄 ↻ ⌫   전체 31,604 건  1 2 3 4 5        │  ← 페이저가 있을 때
└────────────────────────────────────────────┘

┌────────────────────────────────────────────┐
│ … 표 …                                     │
├────────────────────────────────────────────┤
│ 📄 ↻ ⌫                       12 건         │  ← 페이저가 없을 때
└────────────────────────────────────────────┘
```

자리가 둘이라 **둘 다 그려 두고 CSS 로 하나만 보인다.** 어느 쪽인지 코드로 미리
알기 어렵기 때문이다(프리셋·전역·화면 설정이 겹쳐 정해진다).

| 그리드 | 그리는 자리 | 어떻게 |
|---|---|---|
| 페이저 있음 | 페이저 줄 **왼쪽 끝** | `pagerConfig.slots.left` → `VxePager` 의 `left` 슬롯 |
| 페이저 없음 | 표 아래 줄 | 그리드의 `bottom` 슬롯 |

페이저 영역이 실제로 붙어 있으면 아래쪽 것을 숨긴다 —
`.vxe-grid--bottom-wrapper:has(~ .vxe-grid--pager-wrapper)`.
둘은 형제이고 `bottom` 이 먼저 온다(vxe 배치 순서: Table → Bottom → Pager).

**화면이 `bottom` 슬롯에 넣은 내용은 같은 줄을 나눠 쓴다** — 도구 아이콘이 왼쪽,
화면 내용이 그 오른쪽이다. 줄을 둘로 쌓지 않으려는 것이다.
프로젝트관리 `DynamicGrid` 의 '행 추가 · 복사 · N 건' 푸터가 이 방식으로 합쳐졌다
(엑셀 아이콘은 공통 도구줄에 있어서 그쪽에서 뺐다).

### 도구줄을 넣고 나서 화면이 들썩인 것 🟡

> 보고: "`/system/role-map` 과 `/company/user` 의 그리드가 화면이 열린 뒤에
> 세로 크기가 0.5초 간격으로 커진다. 도구줄을 넣은 뒤부터 생긴 현상이다."

이 줄은 **vxe 가 표 높이를 계산할 때 빼는 영역**이다(`getExcludeHeight()` 가
`bottomWrapper` 와 `pagerWrapper` 를 뺀다). 그래서 여기 높이가 흔들리면
표 전체가 다시 그려진다. 흔들릴 수 있는 통로가 셋 있었고 모두 막았다.

| 통로 | 왜 흔들리나 | 막은 방법 |
|---|---|---|
| 슬롯이 매번 새 객체 | 감싸는 부품이 렌더마다 새 슬롯 묶음을 만들어, Vue 가 그리드를 **부모가 그려질 때마다 통째로 다시 그렸다.** 다시 그리면 vxe 가 크기를 다시 재고 그 결과가 또 부모를 건드린다 | 슬롯 묶음에 `$stable: true` |
| 아이콘이 나중에 온다 | iconify 는 SVG 를 비동기로 받는다. 높이를 내용에 맡기면 아이콘이 하나씩 들어올 때마다 줄 높이가 바뀐다 | 도구줄 높이를 **24px 고정**, 줄은 `min-height: 32px` |
| 페이저가 있을 때의 빈 줄 | 도구줄은 숨겨지는데 줄의 테두리·높이는 남아 표 아래에 빈 줄이 생겼다(처음엔 1px, 높이를 주고 나서는 32px) | 줄 모양을 **도구줄이 실제로 보일 때만** 준다 (`:not(:has(~ .vxe-grid--pager-wrapper))`) |

**그리고 진짜 원인은 넷째였다** — 재현 조건을 받고 나서 잡았다.

> "왼쪽 그리드의 행을 클릭하면 오른쪽 그리드에 자료가 뜨는데, 그때부터 길어진다."

`RoleUserTab` 의 그리드는 **위에 도구 줄이 하나 있는 자리**에 놓인다.
그런데 프레임워크가 그리드 바깥에 `h-full`(높이 100%) 을 붙인다 —
이 자리에서 100% 는 남은 높이가 아니라 **도구 줄까지 포함한 높이**다.
그래서 그리드가 도구 줄만큼 넘치고, vxe 가 그 넘친 크기를 다시 재면서 표가
몇 번에 걸쳐 길어졌다.

| | 오른쪽 그리드 높이 |
|---|---|
| 고치기 전 | 815 → 827 → **831** (왼쪽 그리드는 807) |
| 고친 뒤 | 701 → **703** 에서 멈춤 |

고친 방법은 한 줄이다 — `<Grid class="h-auto min-h-0 flex-1">`.
클래스 병합이 tailwind-merge 라 `h-auto` 가 `h-full` 을 밀어내고, 그러면
`flex-1` 이 남은 높이를 정확히 준다.

**아래 도구줄이 이 문제를 드러냈다.** 넘치는 양이 32px 늘고 재계산이 한 번 더
돌면서 눈에 띄게 된 것이지, 높이 사슬 자체는 그전부터 어긋나 있었다.

**같은 형태를 전부 훑었다.** `<Grid>` 에 `flex-1` 을 주는 자리는 셋뿐이고,
`helpdesk/shared/crud-table.vue` 는 이미 `md:h-auto` 로 되어 있었으며
`projmng/shared/dynamic-grid.vue` 는 그리드가 부모의 유일한 자식이라 `h-full` 이 맞다.

> **새 화면을 만들 때**: 그리드 **위에 무언가를 두면** `<Grid class="h-auto min-h-0 flex-1">`
> 로 준다. 그리드가 그 영역의 유일한 자식이면 아무것도 안 줘도 된다.

### 고르는 칸은 여러 개를 고른다 (2026-08-30 추가)

> 추가 지시: "콤보박스와 같이 선택 항목으로 제공하는 필터는 하나만 선택할 수 있다.
> 엑셀의 필터와 같이 여러 개의 항목을 선택할 수 있도록 개선해 줘."

`params.filterOptions` 를 준 칸은 **엑셀 필터처럼 여러 개**를 고를 수 있다.
고른 것 중 **하나라도 맞으면 남는다**(OR).

판정은 여전히 vxe 것을 그대로 쓴다 — 고른 값마다 그 칸의 `filters[].checked` 를
세워 주면 vxe 가 체크된 것들을 차례로 대조해 하나라도 맞는 행을 남긴다.
우리가 거르는 규칙을 새로 짜지 않는다.

세 가지를 함께 챙겼다.

- 목록 팝업을 `body` 에 붙인다. 머리글은 `overflow: hidden` 이라 안에서 열면 잘린다.
- 고른 것이 많아도 **칸 높이가 늘지 않는다**(`maxTagCount: 'responsive'` + 높이 고정).
  이 줄은 vxe 가 표 높이를 계산할 때 쓰는 영역이라, 여기가 커지면 표가 다시 그려진다.
- 아무것도 안 고르면 '전체' 로 보이고, 도구줄의 '필터 초기화' 가 함께 비운다.

값 비교는 `null` · `undefined` · `''` 를 **같은 "값 없음"** 으로 본다.
자료에 셋이 섞여 오기 때문이다 — 그래서 '(없음)' 항목 하나로 셋을 다 잡는다.

### 재조회 아이콘은 조건부다

**눌러도 아무 일 없는 단추를 두지 않는다.**

| 자료를 받는 방식 | 재조회 |
|---|---|
| `proxyConfig.ajax.query` | 자동으로 나온다 (`gridApi.query()`) |
| `:table-data` | `gridFeatures.onRefresh` 를 주어야 나온다 |

`:table-data` 그리드는 그리드가 조회 방법을 모른다. 화면이 이미 갖고 있는
불러오기 함수를 이렇게 연결한다.

```ts
gridOptions: {
  gridFeatures: { onRefresh: () => loadData() },
}
```

`DynamicGrid` 는 자료를 부모가 들고 있어서 `@refresh` 이벤트로 올린다 —
부모가 그것을 받을 때만 아이콘이 나온다.

## 4. 화면에서 조절하는 법

기본은 **켜짐**이다. 목표가 "모든 그리드" 이므로 화면마다 켜게 하면 새로 만드는
화면이 계속 빠진다. 안 맞는 자리에서만 끈다.

| 적는 곳 | 뜻 |
|---|---|
| `gridOptions.gridFeatures: { sort: false }` | 이 그리드는 정렬 안 함 |
| `gridOptions.gridFeatures: { filter: false }` | 이 그리드는 필터줄 없음 |
| `gridOptions.gridFeatures: { tools: false }` | 아래 도구줄 없음 |
| `gridOptions.gridFeatures: { exportName: '계정' }` | 엑셀 파일 이름 |
| `gridOptions.gridFeatures: { onRefresh: () => load() }` | 재조회를 화면이 맡는다 |
| 컬럼 `params: { sort: false }` | 이 칸만 정렬 제외 |
| 컬럼 `params: { filter: false }` | 이 칸만 필터 제외 |
| 컬럼 `params: { filterOptions: [{label,value}] }` | 입력칸 대신 **고르는 칸**(여러 개 선택) |
| 컬럼 `params: { filterText: (row) => string }` | 필터가 훑을 글자를 직접 지정 |

**손대지 않아도 알아서 빠지는 칸** — `type` 이 `seq`·`checkbox`·`radio`·`expand` 인 칸,
`field` 가 없는 칸, `field` 가 `action`·`operation` 같은 조작 칸,
`cellRender.name` 이 `CellOperation` 인 칸, **이미 `slots.header` 를 적어 둔 칸**.

(마지막 규칙에 해당하던 화면은 `/system/menu` 하나였는데, 자체 머리글을 걷어내고
공통 필터줄로 옮겨서 지금은 없다 — 10절.)

## 5. 프레임워크에서 고쳐야 했던 것 둘

### 5.1 설정 병합 순서가 주석과 반대였다

`use-vxe-grid.vue` 의 주석은 "사용자가 전달한 설정이 기본 설정을 덮어씀" 이라고
적혀 있었는데, 실제로는 **거꾸로**였다. `mergeWithArrayOverride` 는 defu 라
**앞선 인자가 이긴다**. 그런데 화면 설정이 맨 뒤에 있었다.

증상: `DynamicGrid` 가 행 단위 편집(`editConfig.mode: 'row'`)을 적어도
프리셋의 `'cell'` 이 이겨서 **칸 하나만 편집기로 바뀌었다.**

우선순위를 이렇게 바로잡았다 — **툴바 > 화면 > 전역 > 프리셋**.
전역을 프리셋보다 위에 남긴 이유는 둘이 겹치는 것이 `border` 하나뿐인데,
지금까지 전역(`false`)이 이겨 왔기 때문이다. 순서를 고치면서 전 화면에 테두리가
갑자기 생기는 것은 이 수정의 목적이 아니다.

**부수 효과(의도한 것)**: 화면이 적어 둔 `pagerConfig: { enabled: true }` 가 이제
실제로 동작한다. 해당 화면은 둘이다 — 다국어 관리, 기상 이벤트. 둘 다 조회 함수가
`page.currentPage` 를 쓰도록 이미 짜여 있었으므로, 그동안 **1페이지만 보이고 넘길
수단이 없던 것**이 고쳐진 셈이다.

### 5.2 페이저가 꺼지면 목록을 못 찾았다

vxe 는 페이저가 **켜져 있을 때만** 응답을 `{ result, page.total }` 로 푼다.
꺼져 있으면 `response.list` 경로(기본값 `'list'`)를 보는데, 우리 API 는 그런 이름을
쓰지 않는다. 그래서 페이저를 끈 화면은 **행이 하나도 안 나왔다.**

전역 `proxyConfig.response.list` 를 함수로 두어 두 모양을 다 받게 했다.

```ts
list: (params) => {
  // vxe 는 응답을 그대로 주지 않고 `{ data, $table, $grid }` 로 감싸서 준다
  const res = params?.data ?? params;
  if (Array.isArray(res)) return res;
  return res?.result ?? res?.items ?? res?.data ?? [];
}
```

> 이 감싸는 규칙을 몰라서 한 번 헛돌았다. `vxe-table/es/grid/src/grid.js` 의
> `listProp(reParams)` 호출부에 있다.

## 6. 화면 이관

### 6.1 `DynamicGrid` (프로젝트관리 21개 화면)

파일 **하나**를 raw `VxeTable` 에서 `useVbenVxeGrid` 로 옮겨 21개가 함께 올라탔다.
부모가 쓰는 것(props · emits · `defineExpose`)은 그대로라 21개 화면은 한 줄도 안 고쳤다.

- 컬럼이 응답마다 달라지는 그리드라 본문·편집기 슬롯을 **하나씩만** 두고
  `column.field` 로 갈라 그린다.
- 행 배열은 `:table-data` 로 넘긴다. `gridOptions.data` 는 프레임워크가 **복제**하므로
  행 추가·복사·삭제(제자리 `splice`)가 표에 반영되지 않는다.
- 푸터의 깔때기 토글은 없앴다. 필터줄이 늘 떠 있어 켜고 끌 것이 없다.

### 6.2 ant-design-vue `<Table>`

`portal/system/push/logs.vue` 를 기준 예제로 먼저 만들고(서버 페이징 31,604건 +
서버 정렬 + 필터줄), 나머지를 같은 규칙으로 옮겼다.

`RoleUserTab.vue` 는 이 요구의 본이 된 화면이라 직접 옮겼다. **그리는 코드가
거의 사라졌다** — 묶음 컬럼 정의 두 벌(200여 줄), `#headerCell` 분기, 필터 상태와
`computed`, 컬럼마다 적던 `sorter` 가 전부 공통 레이어로 갔다.

`helpdesk/shared/crud-table.vue` 는 세 화면이 쓰는 부품이라 **바깥 규격을 그대로 두고**
안쪽만 갈아 끼웠다(`columns` 는 여전히 antd 모양으로 받는다). 그래서
`org/admin` · `org/team` · `project/manage` 는 한 줄도 안 고쳤다.

### 6.3 옮기지 않은 것 하나 🟡

**회사 사용자 관리(`portal/system/company-user/index.vue`)의 가운데 두 표**
(소속 · 미소속)는 antd `<Table>` 로 남겼다.

이 둘은 목록이 아니라 **행을 끌어다 옮기는 장치**다. antd 는 `customRow` 로 행
엘리먼트에 `draggable` 과 드래그 이벤트를 직접 붙일 수 있는데, vxe 에는 그에 해당하는
자리가 없다(자체 행 드래그는 한 표 안에서의 순서 바꾸기용이라 표 사이 이동이 안 된다).
억지로 옮기면 첫 칸을 손잡이로 바꾸는 식이 되어 조작이 달라진다.

같은 파일의 **팝업(사용자 추가 지정) 표는 옮겼고**, 왼쪽 회사 목록은 원래 vxe 였다.
이 두 표를 어떻게 할지는 결정이 필요하다 — 조작 방식이 바뀌어도 좋다면 옮길 수 있다.

## 7. 겪은 함정 (다음 사람을 위해)

1. **컬럼을 나중에 갈아끼우는 화면이 있다.** 부서 관리는 `setGridOptions({columns})`,
   역할-메뉴 탭은 `grid.loadColumn()` 을 쓴다. 둘 다 가로채서 같은 손질을 해 준다.
2. **조회 함수 안에서 `setGridOptions` 를 부르면 안 된다.** 조회가 끝나기 전에 설정이
   바뀌면서 방금 받은 행이 지워진다. 자료를 본 뒤 컬럼을 만들어야 하면 **따로 `watch`** 한다.
3. **전량 조회 그리드는 `pagerConfig: { enabled: false }` 를 적는다.** (5.2 참고)
4. `filterRender` 를 두면 깔때기 팝업에도 입력칸이 생겨 같은 조건을 넣는 자리가
   두 곳이 된다. 공통 레이어가 이미 적혀 있으면 떼어 낸다.
5. 고르는 칸의 빈 값: 자료에서 `null` · `undefined` · `''` 가 섞여 온다.
   공통 레이어의 고르는 칸은 셋을 같게 보므로 값 `''` 하나로 다 잡힌다.
   다만 '전체' 가 이미 `''` 를 쓰므로 **'미지정' 을 따로 두려면 별도 표식이 필요하다**(미해결).

## 10. `/system/menu` 를 공통 레이어로 올렸다 (2026-08-30)

> 지시: "url /system/menu 화면의 그리드는 공통그리드를 사용하지 않는것인가?
> 컬럼필터가 별도의 row 에 표현되지 않고 있다. 공통으로 사용하는 필터형태로 표현해줘."

**왜 빠져 있었나.** 메뉴 관리는 공통 레이어보다 먼저 만든 자체 머리글 필터
(34번 문서 — 한 칸 안에 이름+입력칸, `slots: { header: 'col-filter' }`)를
전 컬럼에 달고 있었다. 공통 레이어는 화면이 직접 그리는 머리글을 덮지 않으려고
`slots.header` 가 있는 칸을 건너뛰므로(9절 규칙), 이 화면만 통째로 제외됐다.

**바꾼 것.**

- `menu/data.ts` — 자체 `textFilter` · `choiceFilter` · `getByPath` 를 지우고
  공통 레이어의 `params` 로 옮겼다. 메뉴명은 `filterText: titleHaystack`(보이는
  이름·번역 키·원래 이름), 컴포넌트는 세 값(component·iframeSrc·link) 합친 글자,
  상태는 `filterOptions`(활성/비활성), 유형은 `CellTag` 옵션에서 저절로 나온다.
- `menu/list.vue` — `#col-filter` 슬롯 · `applyColumnFilter` · 머리글 CSS 보정을
  전부 걷어냈다(공통 레이어가 같은 일을 한다).
- `adapter/vxe-grid-features.ts` — **`gridFeatures.onFilterChange` ·
  `onSortChange` 콜백을 추가했다.** 필터줄과 이름줄 정렬은 `setFilter()` ·
  `grid.sort()` 프로그램 호출이라 vxe 의 `filterChange` · `sortChange` 이벤트가
  오지 않는데, 메뉴 관리는 정렬·필터 중 드래그 저장을 잠가야 해서(34번 문서)
  상태를 바깥에 알릴 수단이 필요했다 — 9절에 적어 두었던 바로 그 조건이다.

**확인한 것** (playwright, 1600×900): 2줄 머리글이 그려지고, 메뉴명 필터
'관리' 로 177→47행, 필터 중 드래그 손잡이 흐려짐(잠금 표시), 필터 초기화로
복원, 이름줄 클릭 정렬에도 손잡이 흐려짐. `pnpm vite build` 통과.

덧: 이 화면의 작업 버튼(하위 추가·수정·삭제)과 등록 버튼이 admin 계정에서
안 보이는 것은 이번 변경 전부터다(stash 후 재확인) — `scom.role_menus` 의
`/system/menu` 권한 데이터 문제로 보이며 별도 사안이다.
