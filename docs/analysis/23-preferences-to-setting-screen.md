# 환경설정을 `/setting/environment` 화면으로

> 지시: "화면 최상단 오른쪽 설정아이콘을 클릭하면 나타나는 설정화면에서
> 관리되는 모든 기능이 `/setting/environment` 화면에서 관리되기를 바란다. 방법은?"

정한 범위(확인받음): **사용자별로 서버에 저장하는 단계까지.** 헤더 톱니는 남긴다.

작업일: 2026-08-26

---

## 1. 손대기 전 상태

| | |
|---|---|
| 톱니 버튼 + 바인딩 | `preferences.vue` (93줄) |
| 드로어 껍데기 + 4탭 + 블록 | `preferences-drawer.vue` (628줄) |
| 저장 위치 | 브라우저 로컬스토리지 (`jsini-portal-web-...-preferences`) |
| `/setting/environment` | "백엔드 연동 준비 중" 임시 화면 |
| `environment-custom` | 없는 API(`#/api/funeral/setting`)를 import 하는 고아 파일 |

**유리했던 점**: `preferences.vue` 의 바인딩이 이미 범용이었다. 설정 항목을 나열하지 않고
`Object.entries(preferences)` 를 훑어 props·listener 를 만든다. 그래서 이 작업은
**설정 항목을 옮기는 일이 아니라 담는 그릇만 바꾸는 일**이었다.

## 2. 구조 — 껍데기만 벗겼다

```
preferences-panel.vue     탭 · 설정 블록 (defineModel 약 60개를 여기가 소유)
preferences-drawer.vue    <Drawer> + 패널        ← 헤더 톱니
preferences-view.vue      페이지 + 패널          ← /setting/environment
use-preferences-binding.ts  스토어 ↔ props·listener (둘이 공유)
use-preferences-actions.ts  초기화 · 설정 복사 · 캐시 삭제 (둘이 공유)
```

껍데기는 **설정 항목을 하나도 모른다.** 바인딩이 만든 props·listener 가 `$attrs` 로
흘러 패널의 `v-model` 이 잡는다. 그래서 설정이 늘어도 고칠 곳은 패널 하나다.
복사해 두면 항목이 늘 때마다 두 곳을 고쳐야 하고, 반드시 한쪽을 잊는다.

`/setting/environment/index.vue` 는 `<PreferencesView>` 를 렌더하는 것이 전부다.

> **2026-09-02 부터 아니다.** 그 화면은 자기 UI 를 갖는다 — 드로어용 부품을 넓은
> 화면에 얹은 것이 어색해서 새로 썼다. 아래 **5.5절**을 읽는다.
> (드로어 쪽 구조는 이 절 그대로다.)

**톱니를 남긴 이유**: 이 화면은 메뉴라서 열람 권한(`scom.role_menus`)이 걸린다.
지금은 4개 역할 모두 열람 가능하지만, 권한 없는 역할이 생기면 그 사람은 자기 테마조차
못 바꾸게 된다. 톱니가 있으면 그 경우에도 길이 남는다.

## 3. 사용자별 서버 저장

### 3.1 DB — [`docs/sql/account_preferences.sql`](../sql/account_preferences.sql) (실행 완료)

`scom.account_preferences` (`id` · `account_id` UNIQUE · `payload jsonb` · 감사 칸).

**`payload` 에는 기본값과 다른 항목만 담는다**(프론트의 `diffPreference`).
전체를 담으면 나중에 프레임워크 기본값이 바뀌어도 옛 값이 박혀 따라오지 않는다.
**그 사고를 이미 겪었다** — 상위 동기화가 `widget.logoutButtonPosition` 기본값을
바꿨을 때 로컬스토리지의 전체 값이 우선해서 새 기본값이 반영되지 않았다.

`jsonb` 인 이유: 설정 항목이 40개가 넘고 동기화마다 늘어난다. 칸으로 쪼개면 항목이
하나 생길 때마다 마이그레이션이 필요하다. 서버는 이 값을 해석하지 않는다.

`account_id` 만으로 키를 잡을 수도 있었지만 `id` + 감사 칸(BaseEntity)을 두어
저장소의 다른 표와 모양을 맞췄다. EF 의 BaseEntity 를 특수 처리하지 않아도 된다.

### 3.2 AuthServer

```
Entities/AccountPreference.cs        payload 는 string + jsonb 매핑
DTOs/AccountPreferenceDto.cs         JsonElement 로 주고받는다
Services/AccountPreferenceService.cs 64KB 상한 · 객체가 아니면 거부 · 깨진 값은 무시
Endpoints/UserEndpoints.cs           GET · PUT /user/preferences
```

**자기 것만 다룬다.** 조회할 계정을 요청에서 받지 않고 게이트웨이가 넘긴 신원을 쓴다.

**저장된 값이 깨져 있어도 화면을 막지 않는다.** 기본값으로 시작하게 둔다 —
설정 하나 때문에 로그인 후 화면이 안 뜨는 것이 훨씬 나쁘다.

### 3.3 프론트 — [`store/preferences-sync.ts`](../../fronts/apps/jsini-portal/src/store/preferences-sync.ts)

로컬스토리지를 **없애지 않았다.** 서버 값을 받으려면 요청이 한 번 오가고, 그동안
화면은 이미 그려진다. 로컬 값이 없으면 기본 테마로 그려진 뒤 튀는 것이 보인다.
그래서 로컬스토리지는 '즉시 그리기용 캐시' 로 두고 서버를 정본으로 쓴다.

`fetchUserInfo()` 에서 한 번만 맞춘다 — 로그인 직후와 새로고침 뒤가 모두 그 자리를
지난다. 저장은 800ms 모아서 보낸다(색을 고르면 값이 연달아 바뀐다).

**로그아웃 때 감시를 먼저 끊는다.** 남겨 두면 로그아웃 과정에서 스토어가 초기화될 때
그 변경을 '사용자가 바꿨다' 로 보고 서버에 덮어써 버린다.

### 3.4 곁들이는 요청은 조용히 실패시킨다

`api/request.ts` 의 공통 오류 처리에 `skipErrorMessage` 를 두었다.

이 인터셉터는 **부르는 쪽이 `catch` 하기 전에** 토스트를 띄운다. 그래서 `.catch()` 만으로는
막을 수 없었고, 백엔드를 아직 다시 띄우지 않은 상태에서 화면마다
"찾을 수 없습니다" 가 떴다. 실제로 그 상태를 보고 고쳤다.

## 5. 헛디딘 것 두 개 (기록해 둔다)

### 5.1 다단(`column-count`)으로 넓게 펴려다 컨트롤을 못 누르게 만들었다

페이지가 넓으니 블록을 여러 단으로 흘리려고 `column-count: 2` 를 걸었다.
**다단은 요소를 단 경계에서 조각내고, 조각난 요소의 좌표와 실제 클릭 영역이 어긋난다.**
그래서 테두리 반경·글꼴 크기를 눌러도 아무 일이 없었다. 값은 정상으로 보이니
바인딩이 깨진 것처럼 보였다 — 찾기 어려운 종류의 고장이다.

`display: grid` 로 바꿨다. 그리드는 요소를 조각내지 않으므로 클릭 영역이 그대로다.
드래그로 순서를 바꾸는 위젯 목록은 다단에서 더 확실히 망가진다.

### 5.2 `radius.vue` 가 고장난 줄 알고 고쳤다가 되돌렸다

`radius.vue` 는 형제 블록과 달리 기본 모델이 없다(`defineModel('themeRadius')` 하나).
부르는 쪽은 `v-model="themeRadius"` 로 기본 모델에 꽂는다. 이름이 어긋나 보여서
고장이라 판단하고 고쳤는데, **실제로는 정상 동작한다** —
선언되지 않은 속성이 루트 `ToggleGroup` 으로 흘러 들어가 값과 이벤트가 모두 이어진다.

원본 상태로 되돌려 실제로 눌러 확인한 뒤 수정을 취소했다. 상위와 다르게 둘 이유가 없다.

**교훈**: 클릭이 안 먹으면 바인딩을 의심하기 전에 **클릭이 그 요소에 닿는지** 먼저 본다
(`document.elementFromPoint(cx, cy)`). 5.1 이 원인이었고 5.2 는 그 오진이었다.

## 5.5 (2026-09-02) 화면을 새로 썼다 — 드로어 부품을 얹는 것을 그만뒀다

> 지시: "`/setting/environment` 는 오른쪽에서 나타나는 설정화면과 함께 쓰고 있다.
> 좁은 영역용 디자인을 같이 쓰다 보니 어색하다. **드로어 쪽은 그대로 두고**
> 이 화면을 데스크톱에서 깔끔하고 설정이 편한 UI 로 완전히 새로 작성하라.
> 설정 처리되는 항목은 누락 없이 모두 존재시켜라."

### 무엇이 어색했나

2절의 판단("껍데기만 벗겨 내용을 공유한다")은 **설정이 갈라지지 않는다**는 점에서는
맞았지만, 공유한 그 내용이 **폭 350px 짜리 서랍을 위해 만든 것**이라는 점을 값으로
치지 않았다. 넓은 화면에서 실제로 이렇게 된다.

| 드로어의 사정 | 페이지에서 생기는 일 |
|---|---|
| `w-41.25`(165px) 고정 폭 컨트롤 | 라벨과 컨트롤 사이가 몇백 px 텅 빈다 |
| 설명을 물음표 툴팁에 숨김 (좁아서) | 넓은데도 설명을 하나하나 눌러 봐야 한다 |
| 탭 넷에 항목 75개를 세로로 쌓음 | 한 탭 안에서 계속 굴려야 한다 |
| 다단(`column-count`)으로 펴려던 시도 | 5.1 에서 이미 실패했다 — 클릭 영역이 어긋난다 |

5절의 헛디딤 둘도 결국 **좁은 부품을 넓은 자리에 억지로 펴려다** 생긴 것이다.

### 어떻게 했나

`apps/jsini-portal/src/views/funeral/setting/environment/` 가 자기 UI 를 갖는다.

```
index.vue                     갈래 목록 + 찾기 + 도구줄 + 항목 그리기
catalog.ts                    항목 정본 — 갈래 13개 · 항목 77개
coverage.test.ts              누락 감시 (아래)
modules/setting-field.vue     한 항목 한 줄 (라벨 · 설명 · 컨트롤)
modules/tile-choice.vue       그림으로 고르기 — 레이아웃 · 본문폭 · 테마 · 전환효과
modules/theme-color-choice.vue 기본 테마 색 + 직접 고르기
modules/widget-order.vue      헤더 위젯 순서 · 위치
```

바뀐 것 넷:

1. **왼쪽에 갈래 목록.** 탭 넷 대신 열셋으로 나눠 한 번에 한 갈래만 그린다.
   갈래마다 "기본값과 다름" 개수를 점으로 보여 준다.
2. **찾기 칸.** 갈래를 몰라도 낱말로 찾는다 — `숨기` 를 치면 사이드바와
   브레드크럼 양쪽에서 걸린다. 항목 77개에서 이것이 가장 크게 편해진 부분이다.
3. **설명을 펼쳤다.** 툴팁을 걷어내고 라벨 아래 한 줄로 적는다.
   드로어에 없던 설명도 새로 썼다(무엇을 켜면 무슨 일이 생기는지).
4. **부품이 antd 다.** 앱의 다른 화면 전부가 antd 이므로 스위치·고르는 칸 모양이 같아졌다.
   컨트롤 폭도 종류에 맞게 뒀다(고르는 칸 224px · 숫자 128px · 입력칸 256px).

### 드로어는 손대지 않았다

`preferences-panel.vue` · `blocks/*` · `preferences-drawer.vue` 그대로다.
2절의 톱니를 남긴 이유가 아직 유효하다 — 이 화면은 메뉴라서 열람 권한이 걸리고,
권한 없는 역할이 생기면 톱니가 유일한 길이 된다.

`preferences-view.vue`(우리가 5절 때 만든 페이지 껍데기)는 **이제 쓰이지 않는다.**
지우지 않고 머리말에 그 사실을 적어 두었다 — 다른 앱이 쓸 수 있는 부품이고,
"이것이 `/setting/environment` 다" 라고 적힌 주석을 남겨 두면 다음 사람이 속는다.

### 항목이 갈라지지 않게 하는 장치

화면이 둘이 되면 **한쪽에만 설정이 붙는 사고**가 난다. 상위(vben)가 설정을 하나
더하면 드로어 패널에는 자동으로 들어오지만 이 화면은 모른다. 그래서:

- 항목을 `catalog.ts` **한 곳에만** 적는다 (화면은 그 목록을 그린다)
- `coverage.test.ts` 가 `preferences-panel.vue` 의 `defineModel` 이름을 읽어 대조한다.
  **하나라도 빠지면 테스트가 깨진다.** 함께 확인하는 것 둘:
  경로↔모델 이름이 맞는가(`sidebar.collapsedShowTitle` ↔ `sidebarCollapsedShowTitle`),
  같은 설정이 두 갈래에 있지 않은가.

```bash
pnpm vitest run --dom apps/jsini-portal/src/views/funeral/setting/environment
```

패널의 모델 **75개 전부**를 덮고 있고, 카탈로그에만 있는 것이 둘이다(아래).

### 덤으로 찾은 것 — 드로어의 단축키 하나가 아무 일도 하지 않는다

`shortcutKeys.globalPreferences`(설정 창 단축키 `Alt ,`)는 스토어에 있고
`blocks/shortcut-keys/global.vue` 에도 스위치가 있는데,
**`preferences-panel.vue` 가 그것을 `v-model` 로 잇지 않았다**
(`v-model:shortcut-keys-preferences` 가 빠져 있다). 그래서 드로어에서 그 스위치를
눌러도 저장되지 않는다. 새 화면은 제대로 잇는다.

**드로어는 고치지 않았다** — "그대로 유지" 지시 범위다. 고치려면 패널에 한 줄
(`v-model:shortcut-keys-preferences="shortcutKeysGlobalPreferences"`)을 더하면 된다.

카탈로그에만 있는 항목 둘이 이것과 `app.enableStickyPreferencesNavigationBar`
(드로어 도구줄의 핀 단추가 다루는 값 — 패널의 `defineModel` 이 아니다)다.

## 6. 남은 것

- **백엔드를 다시 띄워야 서버 저장이 켜진다.** 실행 중인 AuthServer(:5264)와
  게이트웨이(:5265)는 이 변경 전 빌드다. 그전까지 화면은 정상 동작하고
  설정도 로컬스토리지에 남는다 — 서버 저장만 조용히 건너뛴다.
- `environment-custom/index.vue` 는 여전히 없는 API 를 import 하는 고아 파일이다.
  원래 의도(설정그룹·키·값 표 = DB 기반 시스템 설정)는 이번 화면과 성격이 다르다.
  지시 범위를 넘어 손대지 않았다.
- 다음 단계(관리자가 회사·전사 기본값을 정하고 항목별로 잠그는 것)는 하지 않았다.
  하려면 `account_preferences` 옆에 기본값·잠금 표가 하나 더 필요하다.
- 감사 칸의 `created_by` 가 `System` 으로 남는다. AuthServer 는 게이트웨이가 넘긴
  헤더로 신원을 받는데 `HandleAuditing()` 은 `ClaimsPrincipal` 만 본다.
  이 표만의 문제가 아니라 AuthServer 전체가 그렇다 — 별건이라 손대지 않았다.
