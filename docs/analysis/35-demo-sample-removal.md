# 데모 · 샘플 걷어내기

> 지시: "해당 시스템에서 데모와 샘플을 모두 제거 시키고 싶다. 확인해서 진행해 줘."

작업일: 2026-08-28

---

## 1. 먼저 범위를 셌다

데모는 네 뿌리에 몰려 있었고, 하나만 다른 트리에 끼어 있었다.

| 뿌리 | 경로 | 하위 | 상태 |
|---|---|---|---|
| `Demos` | `/demos` | 54 | 이미 꺼져 있었음(`status=0`) |
| `Examples` | `/examples` | 38 | 이미 꺼져 있었음 |
| `VbenProject` | `/vben-admin` | 6 | 이미 꺼져 있었음 |
| `VbenAbout` | `/vben-admin/about` | 0 | **켜져 있었음** |
| `SystemPermSample` | `/system/perm-sample` | 0 | **켜져 있었음** (시스템 트리 안) |

세 뿌리가 `status=0` 인 것은 예전에 누가 한 번 정리를 시도한 흔적이다
(`updated_by = 'demo-menu-cleanup'`). 꺼 두기만 하고 지우지는 않았던 것이다.

지운 양:

| | 지운 것 | 전체 |
|---|---|---|
| `scom.system_menus` | **103** | 266 → 163 |
| `scom.role_menus` (역할↔메뉴 권한) | **412** | 977 → 565 |
| `scom.i18n_resources` (`demos.` · `examples.` 키) | **224** | 1261 → 1037 |
| `scom.menu_favorites` | 0 | 영향 없음 |
| 프론트 파일 | **95** | 453 → 358 |

## 2. 지우기 전에 확인한 것 세 가지

**남는 메뉴가 데모 화면을 쓰지 않는가** — `views/demos` · `views/examples` 를
가리키는 메뉴가 삭제 대상 밖에 하나도 없음을 확인했다. 있었다면 그 메뉴가
빈 화면이 됐을 것이다.

**남는 코드가 데모 다국어 키를 쓰지 않는가** — `demos.` · `examples.` 로 시작하는
키를 쓰는 곳이 데모 폴더 밖에 없음을 확인하고 지웠다.

**폴백 화면은 데모가 아니다** — 데모 메뉴 중에 '폴백 페이지' 묶음이 있어서
`_core/fallback/*`(403 · 404 · 500 · 오프라인)을 가리키고 있었다. 그 파일들은
**진짜 오류 화면**이라 라우터가 직접 쓴다(`router/routes/core.ts` · `access.ts`).
메뉴만 지우고 파일은 남겼다. (지운 뒤 삭제된 데모 주소로 들어가 404 화면이
제대로 뜨는 것으로 확인했다.)

## 3. 되돌릴 수 있게 해 두었다

| 파일 | 무엇 |
|---|---|
| `docs/sql/demo_menu_backup.sql` | 지우기 **직전** 값 739행(메뉴 103 · 권한 412 · 다국어 224)의 INSERT |
| `docs/sql/demo_menu_drop.sql` | 삭제 스크립트. **반복 실행 안전** |

삭제 스크립트는 UUID 를 박아 넣지 않고 **이름으로 뿌리를 찾아 재귀로** 훑는다.
그래서 이미 지운 뒤 다시 돌려도 0건을 지운다(실제로 두 번 돌려 확인했다).

지우는 순서는 외래키를 따른다 — `role_menus` · `menu_favorites` → `system_menus` → 다국어.

## 4. 프론트에서 지운 것

```
views/demos/                     36개
views/examples/                  54개
views/portal/system/perm-sample/  (권한 샘플 화면)
views/_core/about/                (vben 소개)
router/routes/modules/demos.ts · examples.ts · vben.ts
```

**라우트 모듈은 이미 죽어 있었다.** `router/routes/index.ts` 에서
`import.meta.glob('./modules/**/*.ts')` 가 주석 처리돼 있어 `dynamicRoutes` 가
빈 배열이다. 라우트는 DB 메뉴가 만든다. 그래서 이 파일들은 지워도 아무 영향이 없다
(`dashboard.ts` · `system.ts` 도 같은 이유로 죽어 있지만 데모가 아니라 남겨 뒀다).

### 곁따라 지운 store 코드

권한 샘플 화면만 쓰던 것 둘을 함께 걷어냈다. 그 화면이 없으면 부르는 곳이 없다.

- **체험 모드**(`simulation` · `isSimulating` · `startSimulation` · `stopSimulation`) —
  한 경로의 권한만 임시로 덮어써 "이 권한을 켜면 어떻게 보이는지" 를 눌러 보게 하던 것.
- **`hasAnyData`** — 그 화면이 "이 계정은 역할이 없다" 를 알리는 데만 쓰던 값.
  **권한 판단에는 쓰지 않는다.** 예전에 "정보가 없으면 막지 않는다" 로 썼다가
  권한을 하나도 주지 않은 계정이 오히려 전부 열리는 문제가 있었고 그때 가드에서
  걷어냈다. 지금은 비어 있으면 그대로 '권한 없음' 이다.

네 이름 모두 store 와 그 화면 밖에서는 쓰이지 않는 것을 확인하고 지웠다.

## 5. 다시 살아나지 않는다

백엔드(`microservices/**`)와 `docs/sql/*` 어디에도 이 메뉴들을 다시 심는 코드가 없다.
즉 서비스를 재기동해도 돌아오지 않는다.

메뉴는 매번 DB 에서 읽으므로 **AuthServer 재기동도 필요 없다.** 이미 떠 있는
브라우저만 새로고침하면 된다.

## 7. 남은 것 🟡

- **프레임워크(`fronts/packages`)의 데모용 다국어 파일은 건드리지 않았다.**
  그쪽은 vben 상위와 맞춰 두는 영역이라, 지우면 다음 동기화 때 충돌만 늘고
  얻는 것은 없다(쓰이지 않는 문구가 남을 뿐이다).
- 이미 브라우저를 열어 둔 사용자는 **새로고침**하거나 좌측 메뉴의
  '메뉴 다시 읽기' 를 눌러야 사라진 메뉴가 반영된다.
