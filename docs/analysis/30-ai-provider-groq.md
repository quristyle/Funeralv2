# 30. AI 공급자 선택 — JSINI(로컬 LLM) · Groq Free · OpenRouter Free

## 왜

AIAgentServer 는 설정에 적힌 LLM **한 곳**만 봤다(`LLM:ApiBase` 하나).
그 한 곳이 사내 로컬 LLM 장비였고, **자주 꺼져 있어서** 꺼진 동안 AI 기능
전체(채팅 · 공통코드 영문 추천 · 다국어 번역 추천)가 같이 멈췄다.

그래서 공급자를 여러 개 두고 **사용자가 환경설정에서 고르게** 했다.
로컬 장비가 꺼져 있으면 Groq 로 바꿔 계속 쓴다.

## 사용자가 보는 것

환경설정(헤더 톱니 드로어 · `/setting/environment`)에 **AI 탭**이 생겼다.
'사용할 AI 모델' 에서 둘 중 하나를 고른다.

| 값 | 이름 | 실체 |
|---|---|---|
| `jsini` | JSINI (로컬 LLM) | 사내 장비. 지금까지 쓰던 것 (**기본값**) |
| `groq` | Groq Free (클라우드) | 설치 없이 쓰는 무료 클라우드 |
| `openrouter` | OpenRouter Free (클라우드) | 여러 무료 모델 중 골라 쓴다 (아래 별도 절) |

고른 값은 **계정에 붙어 서버에 저장된다**(`store/preferences-sync.ts`).
다른 PC 에서 로그인해도 따라온다. 기본값이 `jsini` 라 **켜기 전과 똑같이 동작한다** —
Groq 를 쓰려면 사람이 골라야 한다.

## Groq 를 고른 이유와 과금

요청한 네 조건을 그대로 확인했다.

1. **서버에 모델을 설치하지 않아도 된다** — 클라우드 API 다.
2. **무료 플랜이 있다** — 결제 수단 등록 없이 가입해서 쓴다.
3. **무료 한도를 넘으면 차단된다** — 초과분이 과금되는 것이 아니라
   `429 Too Many Requests` 로 막힌다. 응답에 `retry-after` 와
   `x-ratelimit-remaining-*` 헤더가 온다.
4. **자동 상향이 없다** — 유료(Developer)로 올리려면 **사람이 결제 수단을 등록하고
   직접 올려야 한다.**

### 과금을 막는 것은 코드가 아니다

> **Groq 계정에 결제 수단을 등록하지 않는 것**이 과금을 막는 장치다.
> 코드가 보장할 수 있는 일이 아니다.

무료 플랜에는 결제 수단이 없으므로 청구될 대상이 없고, 한도를 넘으면 차단된다.
(참고: Groq 의 '지출 한도(spend limit)' 기능은 **유료 플랜 전용**이라 무료 플랜에는
설정할 것이 없다. 필요하지도 않다 — 애초에 청구되지 않는다.)

코드가 하는 일은 그 위에 얹는 안전장치다.

- **재시도하지 않는다.** 실패했다고 자동 재요청하면 한도를 두 배로 태우고,
  429 를 맞은 상태에서는 한도가 풀리는 시각만 뒤로 밀린다.
- **429 를 고장으로 다루지 않는다.** 화면에 "무료 한도를 넘었습니다. N초 후에
  다시 시도하거나 환경설정에서 다른 AI 모델을 선택하세요" 로 나온다.
- **남은 한도를 로그에 남긴다.** 요청 잔량이 20 이하로 떨어지면 경고로 올린다.
- **`MaxTokens` 를 낮게 둔다**(Groq 1024, 로컬 2000). 무료 한도는 분당 토큰(TPM)으로도
  걸리므로, 한 답에 크게 잡으면 그 한 번으로 다음 요청까지 막힌다.
- **`MaxRequestsPerDay` — 우리 쪽 하루 상한. 기본 0(꺼짐).** 숫자를 넣으면 공급자를
  부르기 전에 우리가 먼저 막는다. 과금 방지용이 아니라, 무료 한도를 다 태워
  정작 필요할 때 못 쓰는 것을 줄이는 용도다.

## OpenRouter Free — 무료 모델만 쓴다

### Groq 와 근본적으로 다른 점

Groq 무료 플랜은 **결제 수단이 없으면 청구될 곳이 없다.** 그래서 코드가 할 일이 적었다.

OpenRouter 는 다르다 — **같은 API 로 유료 모델도 부를 수 있다.** 모델 이름 하나만
잘못 들어가면 과금 대상 호출이 된다. 게다가 여기서는 **사용자가 모델을 고르므로**
그 값은 브라우저에서 온 <b>믿을 수 없는 입력</b>이다. 장치가 하나 더 필요했다.

### 세 겹으로 막는다

| 겹 | 무엇 | 어디 |
|---|---|---|
| 1 | 계정에 크레딧·결제 수단을 두지 않는다. 잔액 0 이면 유료 모델은 402 | OpenRouter 계정 (**최종 방어선**) |
| 2 | 부르기 전에 모델이 무료인지 확인한다 | `FreeModelGuard` |
| 3 | 요청 본문으로 유료 경로를 금지한다 | `OpenRouterProviderPrefs` |

**2겹 — 두 조건을 모두 만족해야 무료로 인정한다.**
① 이름이 `:free` 로 끝난다(공급자가 문서로 약속한 규칙) ②
카탈로그(`/api/v1/models`)의 `pricing.prompt` · `pricing.completion` 이 **둘 다 0**.

둘 다 요구하는 근거 — 실측(2026-08-27, 전체 417개):

| | 개수 | 비고 |
|---|---|---|
| `:free` 접미사 | 17 | **전부 실제로 가격 0** (접미사는 신뢰할 수 있다) |
| 가격 0 인데 접미사 없음 | 3 | `openrouter/free`(**자동 라우터**) · lyria 음악 모델 2개 |

`openrouter/free` 는 지금 0 이라도 **어디로 라우팅될지 알 수 없어** 뺀다.
그래서 "가격이 0 이면 통과" 가 아니라 두 조건을 모두 본다.

**3겹 — 요청 본문.** `provider.max_price` 를 전부 0 으로 보낸다. **보장하는 것은 이것이다** —
OpenRouter 가 고를 수 있는 경로가 무료뿐이 된다.

> **`allow_fallbacks` 는 처음에 껐다가 되돌렸다.** "알아서 다른 제공자로 넘긴다" 가
> 유료로 새는 통로처럼 보였는데, 두 가지를 잘못 봤다.
>
> 1. 이 값이 바꾸는 것은 **같은 모델을 서비스하는 상류 제공자**다. 모델 이름은 그대로이고
>    OpenRouter 의 가격은 **모델 이름**에 붙는다 — `:free` 는 누가 서비스하든 0 이다.
> 2. 값이 드는 경로가 있더라도 `max_price=0` 이라 고를 수 없다.
>
> 끄면 **가용성만 잃었다.** 무료 모델의 상류는 자주 일시적으로 한도에 걸리는데
> (`429 … is temporarily rate-limited upstream`), 껐을 때는 그 한 곳에 묶여 그대로 실패했다.
> 실제로 이 때문에 정밀 확인이 계속 429 로 떨어졌다.

### 고른 모델이 무료가 아니면 — 부르지 않고 기본 모델로 돌린다

OpenRouter 는 무료 목록을 수시로 바꾼다. 어제 무료였던 모델이 오늘 사라지는 일이
**정상적으로** 일어난다. 그때

- 그대로 부르면 → 과금된다.
- 오류만 내면 → 사용자 설정 하나 때문에 AI 기능이 멈춘다.

둘 다 안 되므로 **설정의 기본 무료 모델로 바꿔서 답한다.** 바꿨다는 사실은 로그와
상태 화면(`무료 아닌 모델 차단 N회`)에 남는다 — 그것이 뜨면 환경설정의 모델 목록
(`preferences.ts` 의 `AI_OPENROUTER_FREE_MODELS`)을 손볼 때다.

기본 모델까지 무료가 아니면 **부르지 않는다.**

### 환경설정

AI 탭에 항목이 둘이다 — `사용할 AI 모델`(공급자)과 `OpenRouter 모델`.
두 번째는 무료 모델만 나열한다. **이 목록은 편의일 뿐 안전장치가 아니다** —
막는 것은 서버다(위 2·3겹).

지금 실제로 무료인 목록: `GET /api/ai/models?provider=openrouter`.
이 경로는 **가격표만 읽으므로 AI 사용 한도를 쓰지 않는다.**

### 무료 한도

무료 모델은 **분당 20회 · 하루 50회**(크레딧 $10 미만 기준). 넘으면 429 다.

### 실측

| 확인한 것 | 결과 |
|---|---|
| 카탈로그 파싱 | 무료 17종 인식, `openrouter/free` **제외됨**, 기본 모델 무료 확인 |
| `openai/gpt-5` 지정 | 차단 → 기본 무료 모델로 대체 |
| `anthropic/claude-opus-4` 지정 | 차단 → 대체 |
| `openrouter/free` 지정 | 차단 → 대체 (자동 라우터는 통과 못 한다) |
| `google/gemma-4-31b-it` 지정 | 차단 → `…-it:free` 로 대체 (**유료 쌍둥이**를 접미사만으로 구분) |
| 차단 기록 | `count=4`, `from`/`to`/`reason` 모두 기록 |

**공급자가 실제로 받은 본문**(로컬 에코 서버로 가로채 확인):

| 보낸 것 | 실제 본문의 `model` | 실제 본문의 `provider` |
|---|---|---|
| openrouter + `z-ai/glm-5.2:free` | `z-ai/glm-5.2:free` | `allow_fallbacks:false`, `max_price` 전부 0 |
| openrouter + `openai/gpt-5` | **`google/gemma-4-31b-it:free`** (유료 이름은 나가지 않았다) | 같음 |
| groq | `openai/gpt-oss-20b` | **항목 없음** (다른 공급자를 오염시키지 않는다) |

프론트에서 모델을 보내는 조건도 확인했다 — `jsini`·`groq` 는 `(안 보냄)`,
`openrouter` 만 모델을 싣는다. 공급자를 바꿔도 모델 설정은 남아 있으므로,
OpenRouter 모델 이름이 Groq 로 새어 나가면 400 이 된다.

### 키를 넣은 뒤 — 실제 생성까지 확인했다 (2026-08-27)

| 항목 | 결과 |
|---|---|
| 정밀 확인 `?provider=openrouter` | `ok=true` · `generated=true` · 4.9초 (`minimax/minimax-m3:free`) |
| 한국어 채팅 | 정상. 품질이 Groq 의 `gpt-oss-20b` 보다 눈에 띄게 좋다 |
| 공통코드 추천 | `안치실` → `SAFETY_ROOM` (형식은 맞고 도메인 정확도는 낮다 — D-A1 과 같은 한계) |
| **유료 모델 지정(`openai/gpt-5`)** | **차단 후 무료 모델로 답했다** — `1+1은 2입니다.` · 기록 `openai/gpt-5 ↛ minimax/minimax-m3:free` |
| 사용량 기록 | 성공 4 · 실패 1. OpenRouter 는 `x-ratelimit-*` 헤더를 주지 않아 잔량 막대는 안 뜬다 |

유료 모델을 지정한 경우가 이 기능의 핵심 증거다 — **사용자는 답을 받았고, 그 답은
무료 모델이 만들었고, `openai/gpt-5` 는 OpenRouter 에 가지 않았다.**

### 무료 모델은 "이름만 무료" 인 경우가 많다

무료 모델의 상류 제공자는 자주 붐빈다. 이름이 목록에 있어도 그 순간 429 일 수 있다.
그래서 **기본 모델은 실제로 응답하는 것으로 골라야 한다.** 실측:

| 모델 | 결과 |
|---|---|
| `minimax/minimax-m3:free` | **200 · 한국어 깔끔** (GMICloud) → **기본값** |
| `nvidia/nemotron-3-super-120b-a12b:free` | 200, 다만 생각 과정이 섞여 나옴 |
| `google/gemma-4-31b-it:free` | 계속 429 (처음 기본값이었다 — 그래서 바꿨다) |
| `google/gemma-4-26b-a4b-it:free` | 계속 429 |
| `z-ai/glm-5.2:free` | 계속 429 |
| `thinkingmachines/inkling:free` | 403 (이 키로 접근 불가) → 목록에서 제외 |

429 는 고장이 아니라 그때 붐빈 것이라 목록에는 남겨 두었다(시간이 지나면 풀린다).
환경설정 목록의 **순서가 뜻을 가진다 — 첫 번째가 기본값**이고, 실제로 답한 것을 앞에 둔다.

### 429 문구를 고쳤다

처음에는 429 를 전부 "무료 사용 한도를 넘었습니다" 로 보여 줬다. **틀렸다** —
OpenRouter 의 429 는 대개 "상류가 잠깐 붐빔" 이고, 사람이 할 일이 완전히 다르다
(몇 초 뒤 재시도 vs 내일까지 대기). 이제 공급자가 준 원문
(`error.metadata.raw`)을 함께 올린다.

```
OpenRouter Free 이 요청을 받지 않았습니다(한도). 잠시 후에 다시 시도하거나
환경설정에서 다른 AI 모델을 선택하세요.
(공급자 설명: google/gemma-4-31b-it:free is temporarily rate-limited upstream…)
```

## 대기 시간 — 두 가지로 나눠 잡는다

로컬 LLM 이 꺼져 있으면 **21초를 기다린 뒤** 실패했다. 이 기능을 만든 이유가
"로컬이 자주 꺼진다" 인데, 꺼진 상태의 체감이 가장 나빴다.

원인은 대기 시간이 하나뿐이었다는 것이다. `HttpClient` 기본값(100초)에 맡겨져
있었고, 접속 실패는 운영체제 재시도에 걸려 21초가 걸렸다.

**하나로 두면 둘 중 하나가 반드시 망가진다.** 짧게 잡으면 정상적으로 오래 걸리는
생성이 끊기고, 길게 잡으면 꺼진 장비를 오래 기다린다. 그래서 나눴다.

| 설정 | 뜻 | 기본값 |
|---|---|---|
| `AI:ConnectTimeoutSeconds` | **접속**까지. 장비 꺼짐을 알아채는 값 | 5초 (공통) |
| `AI:Providers:<키>:TimeoutSeconds` | **생성**까지. 공급자별 예산 | jsini 120초 · groq 60초 |

접속 대기는 **연결이 맺어진 뒤에는 적용되지 않는다.** 짧게 잡아도 생성이 끊기지
않으므로 공급자별로 나누지 않았다 — 살아 있는 상대는 로컬이든 Groq 든 1초 안에 붙는다.
(`SocketsHttpHandler.ConnectTimeout` 이라 핸들러 단위 설정이기도 하다.)

생성 대기는 `HttpClient.Timeout` 이 아니라 **요청마다 `CancellationTokenSource`** 로 건다.
`HttpClient` 는 하나뿐이라 공급자별로 다르게 둘 수가 없다(그래서 `HttpClient.Timeout`
자체는 끈다).

**스트리밍은 첫 응답까지만 걸린다.** `ResponseHeadersRead` 로 부르므로 헤더가 오면
`SendAsync` 가 돌아오고, 그 뒤 본문이 흘러나오는 동안에는 이 시계가 관여하지 않는다 —
길게 답하는 것이 잘못은 아니다.

실측:

| 경우 | 이전 | 이후 |
|---|---|---|
| 로컬 LLM 꺼짐 (대화) | 21.0초 | **5.03초** |
| 로컬 LLM 꺼짐 (스트리밍) | 21.2초 | **5.01초** |
| Groq 정상 | 0.77초 | 0.58~0.85초 (영향 없음) |
| Groq 응답 대기 1초로 낮춤 | — | 1.03초에 시간 초과 |
| 위와 같은 설정으로 **스트리밍** | — | 1.51초 동안 358조각 정상 수신 (끊기지 않음) |

문구도 원인별로 가른다. 사람이 할 일이 다르다.

- 접속 실패 → `JSINI (로컬 LLM) 에 5초 안에 접속하지 못했습니다. 장비가 꺼져 있거나 주소가 잘못됐을 수 있습니다.`
- 생성 초과 → `Groq Free 이 60초 안에 응답하지 않았습니다. 잠시 뒤에 다시 시도하거나 환경설정에서 다른 AI 모델을 선택하세요.`

`ConnectTimeout` 이 걸리면 .NET 이 영어 문장을 담아 준다("A connection could not be
established within the configured ConnectTimeout."). 그대로 올리면 화면에 영어가 뜨고
무엇을 해야 하는지도 알 수 없어서, `TimeoutException` 을 알아보고 위 문구로 바꾼다.

상태 화면의 공급자 줄에 `대기 — 응답 120초 · 접속 5초` 로 함께 보여 준다.

## 자동 전환 (D-A3 — 켰다)

고른 공급자에 **접속하지 못하면** 다른 공급자로 넘겨 답을 만든다.
`AI:FailoverOnConnectFailure` (기본 `true`).

### 넘기는 조건은 하나다 — 상대에 아예 닿지 못했을 때

이 조건이 좁은 것이 설계의 핵심이다. 넘기지 **않는** 경우:

| 경우 | 왜 넘기지 않나 |
|---|---|
| 생성 시간 초과 | 느린 답 하나가 **양쪽 예산을 다 쓴다.** 이미 기다린 뒤 또 기다리게 된다 |
| 무료 한도 초과(429) | 고장이 아니라 안내다. 몰래 넘기면 **한도가 두 곳에서** 준다 |
| 인증 실패(401) | 설정 문제다. 넘겨서 답이 나오면 **키가 틀렸다는 사실이 안 드러난다** |
| 그 밖의 HTTP 오류 | 상대가 응답은 하고 있다. 접속 문제가 아니다 |

접속 실패는 **넘기지 않아도 어차피 실패**하므로 잃을 것이 없다. 접속 대기가 5초라
전환 비용도 그만큼이다.

넘길 수 있는 상대는 **설정이 끝난 공급자**뿐이다 — 키를 안 넣은 곳으로 넘기면
'접속 실패' 가 '설정 미완' 으로 바뀌기만 하고 사용자는 여전히 답을 못 받는다.

### 조용히 넘어가지 않는다

말없이 다른 모델로 답하면 "왜 말투가 달라졌지" 를 설명할 방법이 없다.

- **스트리밍 답 앞에 한 줄** — `ℹ️ JSINI (로컬 LLM) 에 접속할 수 없어 Groq Free 로 답합니다.`
- **로그** — `jsini 에 접속하지 못해 groq 로 자동 전환합니다. (사유: …)`
- **상태 화면** — AI 공급자 블록에 `자동 전환 2회 / JSINI (로컬 LLM) ↛ Groq Free (접속 실패)`.
  횟수가 쌓이면 장비를 손봐야 한다는 신호다.

### 정밀 확인은 전환하지 않는다

`ChatAsync(..., allowFailover: false)` 로 부른다. 이 버튼은 "이 공급자가 되는가" 를
보는 **진단**이다. 다른 공급자가 대신 답해 버리면 **꺼져 있는 장비를 '정상' 이라고
보고**하게 된다.

### 공급자가 바뀌면 상한도 다시 계산한다

`max_tokens` 는 공급자마다 다르다(로컬 2000 · Groq 1024). 전환된 뒤에도 원래
공급자의 값을 쓰면 Groq 한도를 넘긴 요청을 보내게 되므로, 요청 본문을 **후보마다
다시 만든다.**

### 실측

| 경우 | 결과 |
|---|---|
| jsini(꺼짐) 로 대화 요청 | **5.5초에 Groq 가 답** (`1 + 1은 2입니다.`) · 기록 `jsini→groq` |
| 같은 요청, 스트리밍 | 5.6초, 답 앞에 전환 안내 한 줄이 붙음 |
| 정밀 확인 `?provider=jsini` | `ok=false` — **전환하지 않고** 실패를 그대로 보고 |
| 정밀 확인 `?provider=groq` | `ok=true` (0.55초) |
| groq 하루 상한 1회로 두고 2회 호출 | 2회차 **429, 전환 없음**(`lastFailover: null`), 3ms 에 차단 |

## 설정

`microservices/AIAgentServer/appsettings.json` (추적) — 주소 · 모델 · 상한.
**키는 `appsettings.Local.json` 에만 둔다**(결정 D1-B). 추적 파일에는
`__SET_IN_appsettings.Local.json__` 자리표시자가 있고, 그것이 그대로면 호출하지 않고
"설정이 완료되지 않았습니다" 로 알려 준다 — 키 없이 부르면 401 이 와서
'인증 실패' 로 원인을 잘못 짚게 되기 때문이다.

```jsonc
// appsettings.Local.json
"AI": {
  "DefaultProvider": "jsini",
  "Providers": { "groq": { "ApiKey": "gsk_..." } }
}
```

### 할 일 — Groq 키 발급

1. <https://console.groq.com> 가입 (**결제 수단은 등록하지 않는다**)
2. <https://console.groq.com/keys> 에서 API 키 생성
3. `appsettings.Local.json` 의 `AI:Providers:groq:ApiKey` 에 붙여넣기
4. AIAgentServer 재기동 (`dev.bat ai`) — **`appsettings` 변경만으로는 재기동하지 않는다**

키를 넣기 전까지 Groq 를 골라도 동작하지 않는다. 그 상태가 화면에
그대로 보이므로(아래 `/providers`) 헷갈리지는 않는다.

### 옛 설정 되받기

`AI:Providers:jsini` 가 비어 있으면 **옛 `LLM:*` 를 jsini 공급자로 읽는다.**
그 값들은 각 개발 PC 의 `appsettings.Local.json`(git 제외)에 들어 있어 저장소에서
한꺼번에 고칠 수 없다. 되받기 덕분에 이 변경으로 기존 개발 환경이 깨지지 않는다.

## 구조

```
환경설정(AI 탭)  →  preferences.custom.aiProvider  (계정에 저장)
                        ↓
        api/portal/ai/provider.ts : currentAiProvider()
                        ↓  요청마다 provider 를 붙인다
   /ai/chat · /ai/chat/stream (본문)  ·  /ai/suggest-code · /ai/suggest-i18n (쿼리)
                        ↓
        AiProviderRegistry.Resolve(provider)  →  AiProvider
                        ↓
                    LLMService
```

**공급자는 API 함수 안에서 읽는다.** 화면마다 "환경설정을 읽어 넘겨라" 를 기억해야
하면 언젠가 한 곳을 빠뜨리고 그 화면만 조용히 다른 모델로 돈다. 떠 있는 AI 채팅
위젯은 레이아웃이 `provide` 로 함수를 넘기는 구조라 화면이 직접 부르지도 않는다.

모르는 공급자 이름이 오면 **조용히 기본값으로 되돌린다.** 선택값은 사용자 브라우저에
남아 따라오는데, 나중에 공급자 이름을 바꾸면 옛 값을 든 브라우저가 생긴다.
그때 오류를 내면 AI 기능이 통째로 멈춘다.

### 새로 생긴 엔드포인트

`GET /api/ai/providers` — 설정된 공급자 목록과 **실제로 쓸 수 있는 상태인지**
(`configured`). 키를 안 넣었으면 `false` 다. **키 자체는 절대 내보내지 않는다.**

`POST /api/ai/health/deep?provider=groq` — 정밀 확인을 공급자별로 한다.
로컬이 꺼져 있을 때 Groq 는 멀쩡한지 따로 봐야 하기 때문이다.
한도 초과는 `rateLimited: true` 로 구분해서 준다(고장이 아니다).

### 상태 화면 (`/system/server-status`)

**AI 공급자 블록.** AIAgentServer 를 고르면 고를 수 있는 공급자 전부가 뜬다 —
기본 여부 · 사용 가능/미설정 · 모델 · 최대 토큰 · **사용량** · 공급자별 정밀 확인.

사용량은 **실제 요청이 오갈 때 지나간 응답 헤더를 서버가 주워 둔 값**이다
(`AiUsageTracker`). 사용량을 알려고 공급자를 따로 찔러 보지 않는다 —
**그 조회 자체가 무료 한도를 깎는다.** 그래서

- 한 번도 부르지 않은 공급자는 '아직 호출 기록이 없습니다' 로 뜬다.
- 숫자 옆에 **'n분 전 기준'** 을 함께 보여 준다. 언제 기준인지 모르면 잔량을
  믿고 판단할 수 없다.
- 한도 헤더를 주지 않는 공급자(로컬 LLM)는 막대 없이 호출 성공/실패만 뜬다.

`/health` 의 `llm` 점검은 기본 공급자 하나를 본 결과라 이 블록의 그 공급자 줄과
내용이 겹친다(모델 · 주소). 그래서 **'연결 대상' 에서는 빼고 해당 공급자 줄에
'자동 점검' 으로 붙였다.**

**세로 스크롤을 없앴다(준수사항 4).** 서비스마다 큰 카드를 3열로 늘어놓던 것을
**타일 + 상세 패널**로 바꿨다. 서비스가 9개가 되자 카드가 3줄이 되어 페이지가
스크롤됐고, MSA 는 계속 늘어날 것이라 카드를 조금 줄이는 식으로는 곧 다시 넘친다.

| | 이전 | 이후 |
|---|---|---|
| 배치 | 큰 카드 3열 | 타일(폭에 맞춰 `auto-fill`) + 상세 1개 |
| 스크롤 없이 담기는 서비스 | 6개 (9개에서 이미 넘침) | **24개** (1280×720 기준, 4열×6행) |
| 넘칠 때 | **페이지가** 스크롤 | 타일 칸 **안쪽만** 스크롤 |

상세를 늘 한 개만 그리므로 서비스가 늘어도 화면 높이가 변하지 않는다.
처음 열면 **문제 있는 것(DOWN → DEGRADED)** 이 먼저 선택된다 — 그것이 보러 온 이유다.
선택은 `cluster::destination` 키로 붙들어 10초 자동 새로고침에도 흔들리지 않는다.

곁들여 고친 것:
- 클러스터 이름 두 개가 표에 없어 ID 가 그대로 나왔다 — `notification-cluster`
  (`notify-cluster` 로 잘못 적어 두었다) · `oadr-cluster`.
- `oadr-cluster` 는 **우리 서비스가 아니다**(외부 고객사 시스템, 헬스체크 대상 아님).
  이름을 그대로 두면 우리 MSA 하나가 죽은 것처럼 읽혀서 'OADR (외부)' 로 밝혔다.
- 화면 아래 설명 문단을 헤더의 `?` 툴팁으로 접었다. 자주 읽는 글이 아닌데 세로를 먹었다.

### 헬스체크는 기본 공급자만 본다

`/health` 의 `llm` 항목은 **기본 공급자**를 대표로 본다. 헬스체크는 서버 전체의
상태를 말하는 자리라 특정 사용자의 선택을 따라갈 수 없다. 전부 찔러 보게 하면
점검 한 번에 여러 곳이 붙어 느려지고, **Groq 는 그 점검만으로도 무료 한도를 깎는다.**

## 확인한 것 / 확인하지 못한 것

확인했다 (Release 빌드를 별도 포트로 띄워 직접 호출):

| 항목 | 결과 |
|---|---|
| `/providers` | jsini(기본, configured) · groq 두 개. 이름 · 모델 정상 |
| Groq 키 미설정 상태로 호출 | 부르지 않고 "설정이 완료되지 않았습니다" (502) |
| 모르는 공급자 이름 | 기본(jsini)으로 되돌아감 |
| `X-AI-Provider` 헤더 | 본문 없이도 공급자 지정됨 |
| **Groq 실제 연결** | `https://api.groq.com/openai/v1/chat/completions` 에 실제로 닿아 Groq 가 준 `Invalid API Key` 를 "인증에 실패했습니다" 로 변환 |
| 하루 상한(2회로 두고 3회 호출) | 1·2회는 Groq 까지, **3회는 우리가 429 로 차단** |
| `/suggest-code?provider=` | 쿼리로 공급자 지정됨 |
| `/chat/stream` 실패 | 이유가 본문으로 흘러 화면에 그대로 보임 (예전엔 "⚠️ 오류가 발생했습니다." 한 줄) |
| 환경설정 AI 탭 | 탭 생성 · 두 항목 · 선택값이 계정에 저장됨 |
| 요청 본문 | `{"messages":[…],"provider":"groq"}` — 고른 값이 실제로 실려 나감 |

**키를 넣은 뒤 실제 생성까지 확인했다** (2026-08-27):

| 항목 | 결과 |
|---|---|
| 정밀 확인 `?provider=groq` | `ok=true` · `generated=true` · 442~581ms |
| 정밀 확인 `?provider=jsini` | `ok=false` — 로컬 장비가 실제로 꺼져 있었다 (구분해서 보고됨) |
| 한국어 채팅 | 정상 생성. 인코딩 문제 없음 |
| 공통코드 추천 | `SNAKE_CASE` 한 줄. 형식 정상 |
| 자연어 추천(`natural=true`) | `Title Case` 한 줄. 형식 정상 |
| 다국어 추천 | ko/en 각각 한 줄. 형식 정상 |
| 스트리밍 | SSE 조각으로 실제 생성 도착 |

여전히 확인하지 못한 것: **실제 429(무료 한도 초과).** 한도를 진짜 넘겨야 나온다.
같은 경로를 타는 우리 쪽 하루 상한으로 429 응답 · 문구 · `rateLimited` 구분은 확인했다.

### 실제 무료 한도 (`openai/gpt-oss-20b`, 응답 헤더에서 확인)

| 항목 | 값 |
|---|---|
| 하루 요청 | **1,000회** |
| 분당 토큰(TPM) | **8,000** |

TPM 이 8,000 이라 `MaxTokens` 를 낮게 둔 판단이 맞았다 — 한 답에 2,000 을 잡으면
답 네 번에 1분 한도를 다 쓴다. Groq 를 1024 로 둔 이유다.

### 추론(reasoning) 모델 주의 — 코드로 막았다

일부 모델은 답 앞에 `<think>…</think>` 로 생각을 쏟아낸다. 그 길이가 `max_tokens`
를 넘으면 **생각이 잘린 채 그것이 답으로 돌아온다.** `qwen/qwen3.6-27b` 로
재현했다 — 걸러 내지 않으면 `"Here's a thinking process…"` 가 **공통코드 값으로
DB 에 저장된다.**

`LLMService.CleanOneLiner` 가 처리한다.
- `<think>…</think>` 를 지운다(여러 개도 처리).
- 닫히지 않은(잘린) 블록은 그 뒤 전부를 버린다.
- 남는 것이 없으면 빈 결과로 다뤄 **"생각 과정만 반환하는 모델일 수 있습니다 —
  설정의 Model 을 바꿔 보세요"** 로 알린다.
- 지시를 어기고 설명을 덧붙인 경우 **첫 줄만** 취한다.

`MaxTokens=60` 으로 강제로 잘라서 확인했다 — 502 + 위 문구가 나오고,
쓰레기 값이 통과하지 않는다.

## 한도에 걸리면 다른 무료 모델로 (2026-08-28)

> 지시: "사용자가 지정한 것을 우선 사용하도록 하고, 사용 리미트가 걸리면 자동으로
> 다른 free 모델로 전환되도록 처리해 줘. 주의할 점은 사용 모델은 반드시 :free 모델이어야 한다."

### 층이 둘이다 — 섞으면 안 된다

이미 있던 **공급자** 자동 전환(위 'D-A3')과 이번에 넣은 **모델** 바꿔치기는
조건이 정반대다. 한 곳에 뭉개면 둘 다 틀린다.

| | 언제 넘기나 | 한도(429)에 걸리면 |
|---|---|---|
| 공급자 전환 (jsini → groq) | **닿지 못했을 때만** | 넘기지 **않는다** — 두 곳의 한도가 같이 준다 |
| 모델 바꿔치기 (같은 공급자 안) | **한도에 걸렸을 때** | 바로 이것이 조건이다 |

모델 쪽에서 한도가 전환 조건이 되는 이유 — OpenRouter 의 무료 모델은
**상류 제공자가 각각 다르다.** 한 모델이 붐빈다고 다른 모델이 붐빈 것이 아니다.
반대로 공급자를 넘기는 것은 서로 다른 계정의 한도를 태우는 일이라 조건이 다르다.

### 429 를 두 갈래로 나눴다

이 구분이 이번 작업의 핵심이다.

| 무엇 | 공급자 문구 | 우리가 하는 일 |
|---|---|---|
| **모델 하나가 붐빔** | "… is temporarily rate-limited upstream" | 다음 무료 모델로 바꿔 부른다 |
| **계정 하루 한도** | "Rate limit exceeded: free-models-per-day" | **바꾸지 않는다** |

계정 한도는 **무료 모델 전체가 공유**한다. 그 상태에서 모델을 바꿔 시도하는 것은
남은 몫을 태우기만 하고 결과는 똑같다. 안내 문구도 다르게 준다 —
"모델을 바꿔도 같은 한도를 쓰므로 다른 공급자를 고르세요".

**문구로 판단한다**(`LLMService.LooksAccountWideLimit`). HTTP 상태는 둘 다 429 고
헤더로도 구분되지 않는다. **모르면 '모델 하나' 로 본다** — 그쪽으로 틀리면 요청 몇 개를
더 쓰는 데 그치지만, 반대로 틀리면 바꿔 부르면 답이 나왔을 상황을 실패로 끝낸다.

### 고른 모델을 먼저 쓴다 — 단, 방금 막힌 것을 알면서 또 부르지는 않는다

`AiModelCooldown` 이 한도에 걸린 모델을 잠시 기억한다(`retry-after` 만큼, 10초~30분).
그 사이에는 그 모델을 **뒤로 미룬다.**

기억하지 않으면 매 요청이 **똑같이 막힌 모델을 먼저 부르고** 429 를 받은 뒤에야
넘어간다. 왕복이 하나 늘고, OpenRouter 무료는 **하루 요청 수(50회)**로도 한도가 걸리므로
그 헛호출이 남은 몫을 깎는다.

**빼지 않고 미루기만 한다.** 쉬는 것은 우리 추측이고, 추측 때문에 쓸 모델이 하나도
없게 되면 안 된다. 전부 쉬는 중이면 그래도 순서대로 부른다.

> 만들면서 실제로 틀렸던 곳이다. 처음에는 고른 모델을 언제나 목록 맨 앞에 두어서,
> 쉬는 것을 기억해도 **매번 그 모델을 먼저 불렀다** — 기억이 아무 일도 하지 않았다.
> 시험(2번 항목)에서 드러나 고쳤다.

### 대체 목록은 사람이 정한다 — 카탈로그를 훑지 않는다

`AI:Providers:openrouter:FallbackModels` 에 **순서대로** 적는다.

무료 모델은 지금 17개인데 **서로 대체할 수 있는 것이 아니다.** 코드 전용
(`north-mini-code`), 안전성 분류(`nemotron-3.5-content-safety`), 음악 생성이 섞여 있다.
한도에 걸렸다고 분류 모델로 넘기면 답은 나오지만 **쓸 수 없는 답**이 나온다.
조용히 그렇게 되는 것이 그냥 "한도 초과" 라고 말하는 것보다 나쁘다.

**목록을 비우면 바꿔치기를 하지 않는다** — 예전처럼 한도 초과로 끝난다.
즉 이 기능은 설정으로 켜고 끈다.

`MaxModelAttempts` (기본 3) 로 한 질문당 시도 수를 묶는다. **시도마다 실제 요청이
나가므로** 상한이 없으면 한 번 물어본 것이 하루 몫을 몇 배로 태우고, 사람은
막힌 모델마다 왕복 시간을 기다린다.

### `:free` 보장은 그대로다

대체 모델도 **부르기 전에 무료 확인을 다시 통과해야** 한다(`FreeModelGuard`) —
이름이 `:free` 로 끝나고 카탈로그 단가가 0 이어야 한다. 요청 본문의
`max_price = 0` · `allow_fallbacks = false` 도 그대로 붙는다.
설정 목록에 유료 모델을 잘못 적어도 과금되지 않는다(아래 시험 6).

### 조용히 바뀌지 않는다

| 어디 | 무엇 |
|---|---|
| 채팅 답 앞 | "ℹ️ gemma-4-31b-it 모델이 한도에 걸려 minimax-m3 모델로 답합니다." |
| 상태 화면 | '한도로 모델 전환 n회' (하늘색) · '쉬는 모델 n개' + 복귀까지 남은 시간 |
| 로그 | 429 마다 범위(계정 전체 / 이 모델)를 함께 남긴다 |

상태 화면에서 **'무료 아닌 모델 차단'(노랑)과 따로 뒀다.** 저쪽은 설정 목록을 고쳐야
하는 신호이고 이쪽은 시간이 지나면 풀리는 혼잡이다. 한 칸에 뭉개면 무엇을 해야
하는지 알 수 없다.

**진단(정밀 확인)은 모델도 바꾸지 않는다.** 다른 모델이 대신 답하면 고른 모델이
막혀 있는데 '정상' 으로 보고하게 된다 — 공급자 전환을 끄는 것과 같은 이유다.

### 확인한 것

OpenRouter 를 흉내 내는 스텁(카탈로그 + 모델별 429)으로 격리 인스턴스에서 확인했다.
실제 429 를 일부러 만들어 낼 수는 없어 이 방법을 썼다.

| | 확인 결과 |
|---|---|
| 1. 모델 한 개 혼잡 | `model-a` 429 → `model-b` 호출 → **200 답 수신**. `lastModelRotation` 기록됨 |
| 2. 다음 요청 | `model-a` 를 **아예 부르지 않았다**(스텁 호출 1건, model-b 만) |
| 3. 스트리밍 | 같이 동작하고 답 앞에 "model-a 모델이 한도에 걸려 model-b 모델로 답합니다" 가 붙었다 |
| 4. 계정 하루 한도 | **호출 1건뿐**. 전환 없음, 쉬는 모델 없음, 안내 문구가 "다른 공급자를 고르세요" 로 바뀜 |
| 5. 전부 혼잡 | 3회에서 멈추고(cap=3) 429 로 정직하게 실패 |
| 6. 목록에 유료 모델 | `paid/expensive-model`(:free 아님) · `ddd/not-in-catalog:free`(카탈로그에 없음) **둘 다 호출되지 않고 건너뜀** |

`dotnet build` 오류 0 · `pnpm vite build` 통과 · eslint 새 오류 없음.

### 확인하지 못한 것 🟡

- **상태 화면의 새 칸 두 개(전환 이력 · 쉬는 모델)를 실제 데이터로 그려 보지 못했다.**
  개발 서버에 떠 있는 AIAgentServer 가 이 변경 전 빌드라 `/api/ai/providers` 자체가
  **502** 다(그 화면의 'AI 공급자' 블록은 지금 통째로 비어 있다). 사용자 프로세스를
  재기동하지 않기로 해서 여기까지만 했다. 빌드·린트는 통과했고 템플릿은
  `v-if` + 문자열 두 줄이지만, **그려 본 것은 아니다.**
- **`.NET 설정 배열은 인덱스별로 덮인다.** `appsettings.Local.json` 에
  `FallbackModels` 를 더 짧게 적으면 뒤쪽 인덱스는 `appsettings.json` 의 값이 그대로
  남는다. 시험 중에 실제로 그렇게 섞였다. Local 에서 목록을 바꿀 때는
  **같은 개수로 덮거나** 기본 목록을 비워야 한다.

### 재기동해야 반영된다

설정은 기동 시 한 번만 읽는다. AIAgentServer 를 다시 띄우기 전까지는 예전대로 동작한다.

## 대화 기록과 생각 블록 정리 (2026-08-28)

> 질문: "지금 ai chat 은 대화의 연속성을 위해 지난 대화를 모두 포함하여 요청하고 있다.
> JSINI(로컬 LLM)에서는 그렇게 해야만 대화가 이어졌었다. groq free 나 openrouter free 는
> 그렇게 하지 않아도 될 것 같은데 의견은?"

### 전제를 바로잡았다 — 세 공급자 모두 기록을 보내야 한다

`/v1/chat/completions` 는 **세 곳 모두 상태를 저장하지 않는다.** 서버가 이전 턴을
기억하는 것이 아니라 `messages` 배열이 문맥의 전부다. 로컬 LLM 의 특성이 아니라
**이 API 규격 자체**이고, OpenRouter 는 특히 단순 프록시라 기억할 자리가 없다.
그래서 기록을 빼면 Groq·OpenRouter 에서도 대화가 끊긴다.

(대화 상태를 서버가 들고 있는 API 도 있다 — OpenAI Responses API 의
`previous_response_id` 같은 것. 우리가 쓰는 세 곳은 해당하지 않는다.)

### 그러나 걱정 자체는 맞았다 — 재는 단위가 틀렸다

화면은 '최근 **20개**' 를 보냈다. **개수는 비용의 단위가 아니다** — 짧은 20개와
긴 20개는 열 배 이상 차이 난다. 한도는 글자(토큰)로 걸린다.

그리고 **공급자마다 아픈 곳이 다르다.**

| | 주된 한도 | 기록을 줄이면 |
|---|---|---|
| Groq Free | **분당 토큰(TPM)** | **효과가 크다** |
| OpenRouter Free | **하루 요청 수(50회)** | 거의 효과 없다 — 요청 수는 그대로고 문맥은 수십만 토큰이 들어간다 |
| JSINI (로컬) | 없음 | 속도만 |

그래서 예산을 **공급자별 설정**(`MaxHistoryChars`)으로 두고 **Groq 만 4000자**,
나머지는 `0`(무제한)으로 했다. 지금까지와 달라지는 것은 Groq 뿐이다.

### 자르는 규칙

- 최근 것부터 담다가 예산을 넘으면 멈춘다.
- **반드시 남기는 것 둘** — 지시(`system`)와 **마지막 사용자 질문**.
  지시가 빠지면 말투·언어가 바뀌고, 질문이 빠지면 물어본 것이 없어진다.
  마지막 질문 하나가 예산을 넘어도 그것만은 보낸다(잘라 보내면 질문이 달라진다).
- **공급자마다 다시 자른다.** 자동 전환으로 로컬(무제한)에서 Groq(제한)로 넘어가면
  그쪽 예산에 맞춰야 한다. 원본 목록은 고치지 않는다.
- 브라우저에도 글자 예산(2만자)이 있지만 그것은 **전송 크기를 막는 것뿐**이다.
  진짜 예산은 서버가 정한다 — 공급자별 한도를 브라우저가 알면 두 곳이 어긋난다.

### 생각 블록(`<think>`)을 걷어낸다

한 줄 추천(공통코드·다국어)에는 이미 있던 처리인데 **채팅에는 없었다.**
그래서 추론 모델을 고르면 두 가지가 나빠졌다.

1. 사용자가 "Okay, the user is asking…" 같은 영어 독백을 답으로 읽는다.
2. **그 독백이 대화 기록에 저장되고 다음 턴에 다시 올라간다.** 화면이 받은 것을
   그대로 기록에 쌓기 때문이다. 생각은 보통 답보다 길어서, 턴이 갈수록
   쓸모없는 글자가 문맥의 대부분을 차지하고 한도를 태운다.

**서버에서 걸러 낸다**(`ReasoningFilter`). 화면이 받은 것을 그대로 기록에 쌓으므로
서버에서 빼면 화면과 기록이 한 번에 해결된다. 브라우저에서 빼면 같은 상태 기계를
TS 로 한 번 더 써야 한다.

어려운 점은 **스트리밍에서 태그가 잘려 온다는 것**이다(`<thi` / `nk>`). 그래서
태그의 앞부분일 수 있는 꼬리는 내보내지 않고 들고 있다가, 태그가 아니라고
밝혀지면 그때 내보낸다. 닫히지 않은 생각은 뒤 전부를 버린다 —
`max_tokens` 가 모자라 잘린 경우이고, 그 뒤는 답이 아니라 독백의 조각이다.

전부 생각이었으면 **빈 말풍선을 남기지 않고** 무엇을 해야 하는지 답 자리에 쓴다
("생각 과정만 돌려주고 답을 만들지 못했습니다 — 다른 모델을 골라 보세요").
같은 경우를 비스트리밍(`ChatAsync`)에서는 예외로 올린다 — 상태 화면의
'정밀 확인' 이 그 경로를 쓰는데, 빈 답을 성공으로 보고하면 쓸 수 없는 모델이
'정상' 으로 보인다.

태그를 쓰지 않고 `delta.reasoning` 같은 별도 항목으로 주는 공급자는 애초에
들어오지 않는다(우리는 `delta.content` 만 읽는다).

### 안내를 답과 갈라 놓았다 — 있던 문제도 고쳤다

예전에는 안내("다른 공급자로 답합니다")도 답 글자와 똑같이 스트림으로 나갔다.
그러면 **화면이 그것을 답의 일부로 저장하고 다음 턴 문맥으로 다시 올려보낸다** —
모델이 자기가 하지 않은 말을 자기 말로 읽는다. 이번에 기록을 손대면서 같이 고쳤다.

이제 스트림이 두 모양으로 나간다.

```
data: "글자"                                   ← 답
data: {"notice":"…","kind":"model|provider|history"}   ← 안내
```

화면은 안내를 **말풍선 밖**에 ℹ️ 한 줄로 보여 주고 대화 기록에는 넣지 않는다.
옛 서버는 문자열만 보내므로, 프론트와 서버가 어느 쪽이 먼저 올라가도 깨지지 않는다.

### 확인한 것

스텁으로 격리 인스턴스에서, 그리고 브라우저(개발 서버)에서 확인했다.

| | 결과 |
|---|---|
| 태그가 조각 경계로 쪼개진 생각 (`<thi`+`nk>`) | 답은 `안녕하세요! 무엇을 도와드릴까요?` 만 — 독백 한 글자도 새지 않았다 |
| 생각만 하고 끝(닫히지 않음) | 빈 답이 아니라 "생각 과정만 돌려주고…" 안내가 답 자리에 나왔다 |
| 기록 자르기 (예산 200자) | 25개·1080자 → **4개·166자** 전송. `system` 유지, 마지막 질문 유지, `history` 안내 1건 |
| 예산 안(짧은 대화) | 자르지 않고 안내도 없다 |
| 안내가 답에 섞이는지 | 답은 `pong-…` 뿐, 안내는 객체로만 왔다 |
| 브라우저 | ℹ️ 두 줄이 말풍선 밖에 뜨고, **저장된 답에는 안내 문구가 없다**(`notices` 에 따로 저장) |

`dotnet build` 오류 0 · `pnpm vite build` 통과 · eslint 새 오류 없음.

### 남은 것 🟡

- **예산 4000자는 어림값이다.** 글자와 토큰의 비율은 언어마다 다르고 한국어는
  비싼 편이다. 실제 사용량 헤더(`x-ratelimit-remaining-tokens`)를 보면서
  조정하는 것이 맞다 — 상태 화면에 이미 보인다.
- **AIAgentServer 를 다시 띄워야 반영된다.** 설정은 기동 시 한 번만 읽는다.
