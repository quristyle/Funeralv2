# 계정관리 화면의 MSA 사용자 대조

작성: 2026-08-22
대상 화면: `/system/account`

## 무엇을 했나

포털 계정 목록 옆에 **헬프데스크·프로젝트관리에 그 사람이 어떤 사용자로 있는지**를
함께 보여 준다. 계정 통합 작업을 하려면 "이 포털 계정이 저쪽의 누구인가" 를
먼저 눈으로 확인할 수 있어야 하기 때문이다.

| 컬럼 | 내용 |
|---|---|
| 헬프데스크 | 연결 상태(연결됨/추정) + 이름 + 구분(담당자/고객) |
| 프로젝트관리 | 연결 상태 + 이름 |

마우스를 올리면 로그인 아이디·이메일·소속이 보인다.

## 두 MSA 의 DB 는 건드리지 않는다

지시대로 **읽기 전용**이다. 저장·수정·삭제를 하는 경로가 없다.
그리고 **각 DB 에 직접 접속하지도 않는다** — 서비스가 가진 API 를 게이트웨이 경유로 부른다.

| 소스 | 호출 | 방식 |
|---|---|---|
| 헬프데스크 담당자 | `GET /api/helpdesk/admins` | 읽기 |
| 헬프데스크 고객 | `GET /api/helpdesk/customers` | 읽기 |
| 계정 연결 정보 | `GET /api/helpdesk/auth-links` | 읽기 |
| 프로젝트관리 사용자 | `POST /api/projmng/Proj` → `sp_dev_user_exec` (`p_req_type=R`) | 읽기 |

프로젝트관리는 저장 프로시저로 동작하는데, **조회 모드로만** 부르고
저장·삭제 인자는 넘기지 않는다.

### 왜 서비스 API 로 읽는가

포털이 다른 서비스의 DB 를 직접 읽으면 세 DB 의 스키마가 포털 코드에 박힌다.
저쪽이 테이블을 바꾸면 포털이 조용히 깨진다. 서비스 경계를 넘지 않는 편이 맞다.
(세 서비스가 서로 다른 DB 를 쓴다 — `funeralv2`, `jinrecept`, `jsini`.)

## 한쪽이 죽어도 계정 화면은 뜬다

세 호출은 각각 독립적으로 실패한다. 헬프데스크가 내려가 있으면
그 열만 **'확인 불가'** 로 표시되고, 계정 목록과 프로젝트관리 열은 정상으로 나온다.
마우스를 올리면 실패 사유가 보인다.

## 대조 방식 — '연결됨' 과 '추정' 을 구분한다

| 표시 | 근거 | 신뢰도 |
|---|---|---|
| **연결됨** | `jsini.auth_user_links` 에 관리자가 직접 이어 둔 값 | 확실 |
| **추정** | 로그인 아이디가 같음 → 없으면 이메일이 같음 | **틀릴 수 있음** |

### 왜 굳이 나누는가 — 실제 오탐 사례

검증 중에 이런 결과가 나왔다.

```
포털 로그인       헬프데스크              프로젝트관리
admin            추정 사용자A(담당자)        —
quristyle        연결됨 사용자A(담당자)      추정 사용자A
```

**`admin` 은 서로 다른 사람이다.**

| | 이름 |
|---|---|
| 포털 `admin` | 미르작은사장님 |
| 헬프데스크 `admin` | 사용자A |

로그인 아이디가 우연히 같을 뿐이다. 이걸 '연결됨' 으로 보여 줬다면
관리자가 그대로 믿고 계정을 잇거나 권한을 옮겼을 수 있다.
그래서 **추정은 추정이라고 적는다.**

> 이 사례는 계정 단일화 초기에도 한 번 걸렸던 것이다.
> 그때 로그인 아이디 자동 매칭을 기본 꺼짐으로 둔 이유와 같다.

## 검증

실제 서버·실제 데이터로 확인했다(2026-08-22).

```
포털 계정 5 · 헬프데스크 32 · 프로젝트관리 9 · 연결 1

quristyle    → 연결됨 사용자A(담당자) + 프로젝트관리 사용자A   (정상)
admin        → 추정  사용자A(담당자)                        (오탐 — 표시가 의도대로 작동)
그 외        → —
```

프론트 빌드 통과. 검증용 임시 계정은 삭제했다.

**화면을 눈으로 확인하지는 못했다.** 로그인에 비밀번호 입력이 필요해서다.
데이터 흐름은 실제 API·실제 토큰으로 끝까지 확인했으므로 로직은 검증됐고,
남은 것은 표시가 의도대로 그려지는지뿐이다.

## 앞으로

지금은 **보여 주기만** 한다. 연결을 만들거나 끊는 기능은 넣지 않았다.
연결 관리는 헬프데스크의 `계정 연결` 화면(`/helpdesk/system/account-link`)에 이미 있다.

'추정' 으로 뜨는 사용자를 계정관리 화면에서 바로 '연결됨' 으로 확정하는 버튼을
붙이는 것이 다음 단계로 자연스럽다. 다만 그건 **쓰기** 라서
헬프데스크 DB 를 건드리지 말라는 이번 지시 범위를 벗어난다.
