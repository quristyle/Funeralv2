# 사람 목록에 얼굴 보여 주기 (`/auth/user-role` · `/system/account`)

> 지시: "`/auth/user-role` 왼쪽 사람 목록에 사람 아이콘 대신 아바타를 제공해 줘.
> 아바타에 프로필 사진이 있다면 사진이 보이는 아바타로 처리해 줘.
> 작업이 끝나면 `/system/account` 목록에도 아바타 표현을 추가해 줘."

작업일: 2026-08-28

---

## 1. 사진은 이미 있었는데 목록까지 오지 않았다

프로필 사진은 **프로필 상세의 한 줄**(`account_profile_details.detail_type = 'Avatar'`)에
내려받기 주소로 들어 있다. 계정 테이블의 `avatar_group_id` 는 **파일 묶음**이고,
그중 대표 한 장의 주소가 저 자리에 저장된다. 화면이 바로 쓸 수 있는 것은 주소 쪽이다.

두 목록 모두 그 값을 받지 못하고 있었다.

| | 무엇이 없었나 |
|---|---|
| `/auth/user-role` | `AccountPickDto` 에 사진 칸 자체가 없었다 |
| `/system/account` | `AccountDto` 에는 **칸이 있는데 채우지 않아** 늘 `null` 이었다 |

두 번째가 특히 눈에 띈다 — DTO 주석에는 "썸네일로 바꿔 쓴다" 는 설명까지 적혀 있는데
`GetAccountsAsync` 가 값을 넣지 않았다. 부서 화면(`DepartmentService`)은 넣고 있었다.

### 조회 한 번으로 가져온다

`user-role` 쪽 목록은 계정을 컬럼만 골라 읽는 질의라 프로필 상세가 딸려 오지 않는다.
사람마다 따로 읽으면 목록 한 번에 쿼리가 43번 더 나간다(N+1). 그래서
**`Avatar` 상세만 한 번에 읽어 표로 만든 뒤** 붙인다.

`/system/account` 쪽은 이미 `Include(a => a.ProfileDetails)` 로 읽고 있어
추가 조회 없이 한 줄만 더 꺼내면 됐다.

## 2. 사진이 없는 것은 오류가 아니다

지금 43명 중 사진이 있는 사람은 **한 명**이다. 즉 **없는 쪽이 정상**이고,
빈 동그라미나 물음표를 두면 목록이 온통 '빠진 값' 처럼 보인다.

그래서 사진이 없으면 **이름 첫 글자**를 그린다. 배경색은 이름에서 뽑는다 —
무작위로 고르면 다시 그릴 때마다 색이 바뀌어 눈에 익지 않는다. 이름 글자를 더한
값으로 정하면 **같은 사람은 어느 화면에서나 같은 색**이 된다.

규칙은 `apps/jsini-portal/src/utils/avatar.ts` 한 곳에 둔다. 원래 썸네일 변환은
레이아웃 헤더에만 있었는데(`layouts/basic.vue`), 화면마다 다시 쓰면 한쪽만 원본을
받아 무거워지거나 첫 글자 규칙이 달라져 **같은 사람이 화면마다 다르게** 보인다.

```
avatarThumbUrl()  /api/file/download/… → /api/file/thumbnail/…   (목록에 원본은 무겁다)
avatarInitial()   이름 첫 글자
avatarColor()     이름에서 뽑은 고정 색 8종
avatarStyle()     크기·색을 한 번에
```

## 3. 크기 — antd 와 두 번 부딪혔다

**첫째, 32px 이 박혀 있다.** antd 의 `.ant-avatar` 는 크기를 자기 클래스로 지정해
Tailwind 의 `size-5` 로는 밀리지 않는다. 처음에 클래스로 줬더니 그대로 32px 이 나와
목록 줄이 통째로 두꺼워졌다(실측으로 발견했다). 인라인 스타일로 바꿔 이겼다.

**둘째, `size` 속성은 px 이다.** 숫자를 주면 픽셀로 박혀 **사용자가 정한 글꼴 크기를
따라가지 못한다** — 글자만 커지고 얼굴은 그대로인 화면이 된다. 그래서 `rem` 으로 준다.
루트 14px 기준 목록은 19.25px(1.375rem), 강조 자리는 21px(1.5rem)이 된다.

## 4. 어디에 넣었나

- **`/auth/user-role`** — 왼쪽 목록의 사람 칸, 그리고 고른 사람의 카드 제목.
  회사·부서는 사람이 아니므로 건물·폴더 아이콘을 그대로 둔다.
- **`/system/account`** — **이름 칸 안**에 얼굴을 붙였다. 칸을 따로 만들면 이미 넓은
  표가 더 넓어지고, 사람을 알아보는 데 필요한 두 값이 떨어져 놓인다.
  정렬·필터는 `field` 를 그대로 쓰므로 이름 기준으로 계속 동작한다(아래에서 확인함).

## 5. 확인한 것

**백엔드** — 격리 AuthServer(:15481)를 띄워 직접 불렀다. 개발자가 띄워 둔 것은 건드리지 않았다.

| 경로 | 결과 |
|---|---|
| `/system/account/list` | 43건 중 **1건에 `avatar` 채워짐** (`quristyle`), `avatarGroupId` 도 함께 |
| `/system/role-scope/accounts` | 43건, 키에 `avatar` 추가됨, 같은 1건에 값 |

**화면** — 개발 서버에서 실제로 눌러 확인했다.

| | 결과 |
|---|---|
| `/auth/user-role` 목록 | 아바타 43개, 색 8종, 첫 글자 표시, 크기 19.25px(=1.375rem × 루트 14px) |
| **사진** | `download` → `thumbnail` 로 바뀌었고 이미지가 **실제로 로드됨**(150×150) |
| 고른 사람 카드 제목 | 같은 얼굴이 21px 로 |
| `/system/account` | 아바타 43개, 사진 1개 로드, 줄 높이 40px 그대로 |
| 이름 칸 정렬 | 오름 `사용자B…` / 내림 `ywsname333…` — **동작** |
| 이름 칸 필터 | `김` → 43건에서 5명으로, 전부 `김` 포함 — **동작** |

사진 경로는 개발 서버의 AuthServer 가 아직 이 변경 전 빌드라, 응답에 실제 주소를
끼워 넣어 확인했다. 주소는 DB 에 저장된 진짜 값이고 이미지도 진짜로 내려왔다 —
**썸네일 경로와 `jsini_file_at` 쿠키가 동작한다는 뜻**이다(27번 문서 5절).

`dotnet build` 오류 0 · `pnpm vite build` 통과 · eslint 새 오류 없음.

## 6. 남은 것 🟡

- **AuthServer 를 다시 띄워야 사진이 실제로 붙는다.** 지금 떠 있는 것은 이 변경 전
  빌드라 `avatar` 가 `null` 로 오고, 화면은 전부 첫 글자로 보인다(그 자체는 정상 동작이다).
- 사진이 있는 계정이 하나뿐이라 **여러 장이 섞인 목록은 보지 못했다.** 한 장으로
  확인한 경로가 나머지에도 그대로 적용되지만, 실제로 여러 명이 올린 뒤 한 번 더 보는 편이 좋다.
