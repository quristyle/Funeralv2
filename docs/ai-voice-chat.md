# AI쳇을 말로 쓰는 길

`/site/ai/chat` 과 헤더 서랍에서 **말로 묻고 소리로 듣는다.** 받아쓰기(STT)는
우리 장비가 하고, 읽어주기(TTS)는 브라우저가 한다.

## 어디에 무엇이 있나

| 자리 | 하는 일 |
|---|---|
| `Components/Layout/AiChatPanel.razor(.cs)` | 마이크 단추 · 음성 모드 오버레이 · 상태 가르기 |
| `Components/wwwroot/js/chat-voice.js` | 마이크 열기 · 녹음 · 소리 크기 · 자동 종료 |
| `Components/wwwroot/js/speech.js` | 읽어주기. **프로젝트관리 지시 상세와 같은 것** |
| `JSini.Web.Http/AiChatClient.TranscribeAsync` | 녹음을 게이트웨이로 올린다 |
| `AIAgentServer/Services/SpeechClient.cs` | 받아쓰기 서버를 부른다 |
| `AIAgentServer` `POST /stt` | 그 창구 (게이트웨이로는 `/api/ai/stt`) |
| [deploy/stt/](../deploy/stt/) | 받아쓰기 서버를 올리는 정본 |

## 왜 새 화면이 아니라 같은 부품의 한 상태인가

음성 모드는 **라우트가 아니다.** `AiChatPanel` 안의 전체화면 오버레이다.
새 화면으로 빼면 둘을 잃는다.

- **공용 부품이 갈라진다.** 이 알맹이는 화면 하나와 헤더 서랍이 함께 쓴다
  (`AiChatPanel` 머리말). 음성용을 따로 파면 그 분기가 셋이 되고, 고침이
  한쪽에만 들어가는 어긋남이 「화면에서는 되는데 서랍에서는 안 된다」로 나타난다.
- **메뉴 등록과 권한 배정이 따라온다.** `@page` 가 DB 메뉴 경로와 같아야 하고,
  권한관리 밖의 주소는 기본으로 막힌다([screen-access.md](screen-access.md)).

그리고 **닫으면 대화가 그대로 남는다** — 말로 물은 것이 뒤에 글로 읽힌다.
그것이 이 설계의 요점이라, 세션을 나누는 새 화면과는 애초에 맞지 않는다.

## 받아쓰기와 음성 모드는 다른 UX 다

한 단추에 묶으면 둘 다 어정쩡해진다.

| | 받아쓰기 (마이크 단추) | 음성 모드 (오버레이) |
|---|---|---|
| 말한 것이 | **입력칸에 채워진다** | 바로 질문으로 나간다 |
| 사람이 눈으로 확인 | **한다** | 안 한다(자막으로 본다) |
| 답을 읽어 주나 | 아니다 | 그렇다(끌 수 있다) |
| 끝나면 | 멈춘다 | **다시 듣는다** |

받아쓰기가 바로 안 보내는 까닭 — 받아쓰기는 틀릴 수 있고, 틀린 채로 나가면
사람은 **AI 가 엉뚱한 답을 했다**고 읽는다. 그 확인을 건너뛰는 쪽이 음성 모드다.

## 한 턴이 도는 차례

```
         ┌──────────── 사람이 말한다
         ▼
   [듣는 중]  마이크 열림 · 오브가 맥박친다
         │    조용해지면 스스로 끊거나(VAD) 눌러서 끊는다
         ▼
   [옮기는 중]  녹음 → 회로 → 게이트웨이 → AIAgentServer → 받아쓰기 서버
         ▼
   [답 만드는 중]  글이 질문으로 나간다(SSE 스트리밍)
         │        문장이 될 때마다 읽어주기에 밀어 넣는다
         ▼
   [읽는 중]  ──── 읽기가 끝나면 ────┐
         │                           │
         └── 눌러서 끊으면 ──────────┘
                                     ▼
                              다시 [듣는 중]
```

**읽는 중에 마이크를 열지 않는다.** 열면 제가 읽는 소리를 제가 받아쓴다 —
울림 지우기(`echoCancellation`)를 켜 두었어도 기기에 따라 샌다. 읽기가 끝났다는
소식은 JS 가 준다(`OnSpeechStateChanged`).

**그 소식이 영영 안 올 수 있다** — 그 브라우저에 읽어주기가 없거나 한국어
목소리를 못 잡은 경우다. 그러면 음성 모드가 그 자리에 멎으므로, 스트림이
끝났을 때 `_speaking` 이 거짓이면 기다리지 않고 바로 듣는다.

## 걸린 자리 다섯

### 1. 브라우저 받아쓰기를 안 쓴다

크롬에는 `SpeechRecognition` 이 있고 그것을 쓰면 서버가 필요 없다. 그런데
**아이폰에는 아예 없고**(Safari 미지원) **말소리가 구글 서버로 나간다.**
사내 업무를 말로 묻는 자리라 둘 다 받아들일 수 없다.

잃는 것이 하나 있다 — **말하는 동안 글자가 따라 붙는 실시간 받아쓰기**는 이
길로 안 된다. 녹음이 끝나야 글이 나온다. 그것까지 하려면 소리를 흘려보내는
길(WebSocket)을 따로 열어야 한다.

읽어주기는 반대다. 브라우저 것이 대개 기기 안에서 처리되고 아이폰도 되므로
서버를 안 쓴다.

### 2. 소리는 **회로로** 넘긴다 — 게이트웨이를 직접 부르지 않는다

브라우저가 게이트웨이로 바로 올리는 편이 짧다. 그런데 게이트웨이의 CORS 는
옛 포털 주소(`localhost:5555`) 하나만 열려 있어 개발에서 깨지고, BFF 라
브라우저에 토큰도 없다. 회로의 수신 한도는 이미 4MB 라(`JSiniWebApp`)
한 마디(수십 KB)는 넉넉히 지나간다.

### 3. 소리 크기는 **회로로 보내지 않는다**

오브가 맥박치려면 소리 크기가 계속 필요하다. 그것을 C# 으로 올리면 말하는
동안 초당 수십 번 서버가 깨어난다. **JS 가 CSS 변수에 직접 적고**
(`--jsini-voice-level`) 화면은 그 변수만 본다.

적어 넣을 칸을 넘기는 일은 **그려진 뒤**에 따로 한다(`setMeterTarget`).
`StateHasChanged()` 는 그 자리에서 그리지 않으므로, 여는 일과 한 함수에 묶으면
**아직 없는 칸**을 넘기게 된다.

### 4. 서랍 안에서 열면 `position: fixed` 가 서랍에 갇힌다

열린 서랍은 `transform: translateX(0)` 을 쓰는데, `none` 이 아닌 transform 은
그 안의 고정 자리잡기에 **새 기준 상자**를 만든다. 그래서 같은 알맹이가
화면에서는 화면을 채우고 서랍에서는 26rem 안에 갇힌다.

음성 모드가 떠 있는 동안에만 그 transform 을 거둔다(app.css):

```css
.jsini-right-drawer--open:has(.jsini-voice) { transform: none; }
```

**재어 확인했다** — 그 한 줄 전에는 서랍 안 오버레이가 415×848, 뒤에는
0,0,1280×900 이다.

> **`AiChatPanel` 은 한 화면에 두 벌 떠 있다**(화면 + 헤더 서랍 — 서랍은 닫혀도
> DOM 에 남는다). 그래서 확인할 때 `document.querySelector('.jsini-voice')` 로
> 집으면 **닫힌 서랍 쪽**이 잡힌다. 자리를 좁혀 집는다
> (`.site-ai-chat .jsini-voice` · `.jsini-right-drawer--open …`).

### 5. 문장이 될 때까지 모았다가 읽힌다

답은 글자 단위로 온다. 오는 대로 읽어주기에 넣으면 **한 글자짜리 발화**가
줄줄이 생겨 말이 토막 나고, 다 올 때까지 기다리면 긴 답에서 몇 초 동안 아무
소리도 안 난다. 그 사이가 문장이다(`AiChatPanel.TakeSentence`).

- 문장 끝은 `. ! ? …` 과 줄바꿈. **마침표 뒤가 숫자면 끝이 아니다** —
  「3.14」가 두 동강 나면 읽는 소리가 이상해진다.
- 문장 끝이 안 와도 140자가 넘으면 빈칸에서 끊는다(목록·표처럼 마침표 없이
  길게 가는 글이 있다).

## 화면이 가르는 네 상태

조건을 markup 에 흩으면 오브의 그림·글·애니메이션이 서로 다른 상태를 가리키는
날이 온다. 한 곳에서 가린다(`VoiceStageClass` · `VoiceOrbIcon` · `VoiceStateText`).

| 상태 | 오브 | 눌렀을 때 |
|---|---|---|
| `is-idle` | 회색, 가만히 | 듣기 시작 |
| `is-listening` | 강조색, **소리 크기만큼 커졌다 작아진다** + 고리가 퍼진다 | 끝내고 질문 |
| `is-thinking` | 천천히 **돈다** | 아무것도 (잠긴다) |
| `is-speaking` | 숨 쉬듯 느리게 | **말을 끊고 듣기로** |

생각하는 중을 맥박이 아니라 회전으로 가른 까닭 — 맥박이면 듣는 중과 구별이
안 돼서 사람이 말을 계속 걸게 된다.

**자막은 반드시 띄운다.** 받아쓰기가 틀렸을 때 사람이 알아야 하고, 시끄러운
자리에서 소리를 끄고도 쓸 수 있어야 한다. 자리는 고정해 둔다 — 글 길이에 따라
오브가 위아래로 뛰면 누르기 어렵다. 보여 줄 말이 없을 때도 **빈 상자로 두지
않는다**(안내 한 줄을 깐다).

## 끌 수 있어야 하는 것 둘

| | 기본 | 끄는 까닭 |
|---|---|---|
| 읽어주기 | 켬 | 사무실에서 민폐다 |
| 자동 종료(VAD) | 켬 | 옆자리 말소리에 끊긴다 |

자동 종료는 **입을 떼기 전 2.5초는 세지 않는다**(`LEAD_IN_MS`). 마이크를
열자마자 조용한 것은 당연한데, 그것을 세면 말을 꺼내기도 전에 끊긴다.
녹음은 2분에서 스스로 끊고, 서버도 10MB 에서 한 번 더 막는다.

## 웹이라 못 하는 것

| | 왜 |
|---|---|
| 화면을 끄고 대화 | 서비스워커에 마이크가 없다. 탭을 떠나면 끊긴다 — [geolocation-background.md](geolocation-background.md) 와 같은 맥락이다 |
| 실시간 받아쓰기 | 위 1번. 소리를 흘려보내는 길을 따로 열어야 한다 |
| HTTP 로 들어온 개발 주소 | 마이크는 **보안 맥락**에서만 열린다. `localhost` 는 되고 장비 IP 는 안 된다 |

**이것들 때문에 네이티브 앱을 만들 까닭은 없다.** 아이폰에서 못 쓰는 문제와
말소리가 바깥으로 나가는 문제는 서버측 STT 하나로 풀렸고, 남는 것은 「화면을
끄고 대화」뿐인데 그것은 지금 요구가 아니다.

## 안 될 때

| 화면에 뜨는 말 | 거의 늘 이것이다 |
|---|---|
| 마이크를 열지 못했습니다 | 권한 거절. 그다음이 HTTPS 가 아닌 주소 |
| 이 브라우저에서는 녹음을 쓸 수 없습니다 | `MediaRecorder` 가 없다(아주 오래된 브라우저) |
| 받아쓰기 서버가 404 로… | 장비 nginx 에 `/stt/` 를 안 냈다 — [deploy/stt/README.md](../deploy/stt/README.md) |
| 받아쓰기 서버가 401 로… | nginx 토큰과 `AI:Providers:jsini:ApiKey` 가 다르다 |
| 말소리를 알아듣지 못했습니다 | **고장이 아니다** — 무음을 보냈다 |
| 소리가 안 난다 | 그 브라우저에 한국어 목소리가 없다. 자막은 그대로 돈다 |

서버 쪽 상태는 포털의 **「AI 기능 상태」** 화면이 정본이다(`/features/status` 의
`speech`). 설정만 읽는 것이 아니라 **무음 하나를 실제로 보내 본** 결과를
보여 준다 — 모델을 못 올린 서버는 멀쩡히 200 을 주면서 받아쓰기만 전부
실패하는데, 모델 목록만 물어서는 그것이 안 갈린다.

**받아쓰기가 끊겨도 대화는 멀쩡하다.** 글로 묻는 길은 그대로라 서비스 상태로는
안 갈린다 — RAG·웹 검색과 같은 갈래다.
