# 권한을 바꾸면 다시 로그인하지 않아도 먹는 길

관리자가 사람의 역할(회사·부서·사람 단계)이나 역할의 메뉴 권한을 바꾸면,
열려 있는 포털은 **30초 안에**, 새로고침(F5)한 포털은 **뜨자마자** 새 권한으로 바뀐다.

## 왜 다시 로그인해야만 먹었나

권한이 머무는 자리가 셋이었고, 셋 다 로그인 때 값을 오래 들고 있었다.

| 자리 | 무엇을 | 얼마나 |
|---|---|---|
| 게이트웨이 토큰(JWT) | 역할 식별자(`role` 클레임) | **7일** — 게이트웨이가 이것으로 `X-User-Roles` 를 만들고, 헬프데스크·프로젝트관리는 토큰을 직접 풀어 본다 |
| 셸의 부트스트랩 통(`PortalBootstrapStore`) | 메뉴·권한표·내 정보 | 2분 (열쇠가 로그인 토큰이라 F5 로는 안 바뀐다) |
| 회로 안의 `PermissionContext`·`MenuProvider` | 사이드바·단추·진입 가드 | 레이아웃이 뜰 때 한 번 |

AuthServer 의 메뉴·권한표는 DB 에서 바로 읽으므로, 실제로 「로그아웃해야만」인
것은 **토큰 속 역할** 쪽이다 — 화면에 메뉴가 보여도 저장·조회는 백엔드가 옛
역할로 판정했다.

## 지금의 길

`PortalBootstrap.SyncPermissionsAsync` 가 레이아웃이 뜬 직후와 30초마다(워터마크를
되묻는 같은 차례) 돈다.

1. **권한 지문** — `GET /api/auth/portal/permission-stamp` 가 「적용 역할 +
   메뉴별 권한」을 접은 지문(`PermissionStamp.Of`)을 준다. 부트스트랩도 같은 지문을
   싣는다. 둘이 다르면 통을 거치지 않고 부트스트랩을 다시 받는다 →
   사이드바·권한표·`CurrentUser.Roles` 가 바뀌고, 지금 화면이 막히면 안내로 바뀐다.
2. **토큰의 역할** — 지금 쓰는 토큰의 `role` 클레임(`TokenRoles.Read`)이 DB 의
   역할(`CurrentUser.Roles`)과 다르면 `GatewayClient.RenewTokenAsync` 로 토큰을 새로
   받는다. 갱신(`/auth/refresh`)은 역할을 DB 에서 다시 읽어 싣는다. 새 토큰은
   `RefreshedTokens` 에 로그인 토큰을 열쇠로 담기므로 **F5 뒤에도 이어진다.**

같은 어긋남으로는 토큰 갱신을 한 번만 시도한다 — 갱신이 꺼져 있거나(404) 갱신 쿠키가
죽었으면 30초마다 두드리지 않는다. 그때는 다시 로그인해야 백엔드가 새 역할을 본다.

## 늦게 먹는 것

- **브라우저를 닫아 둔 사람**은 다음에 열 때 위 1·2 가 돈다.
- 셸 밖에서 토큰을 쓰는 것(파일 읽기 쿠키 `jsini_file_at`)은 다음 갱신 때 바뀐다.
- 메뉴 **구조**(새 메뉴·경로)만 바뀐 것은 지문에 안 잡힌다 — 권한이 함께 바뀌면 잡힌다.
  사이드바 오른쪽 클릭 「메뉴 새로 고침」이나 2분 뒤 F5 로 받는다.
