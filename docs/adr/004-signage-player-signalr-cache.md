# ADR 004: 디지털 사이니지 플레이어 기술 스택 및 실시간 캐싱 아키텍처 결정

- **상태**: 승인됨 (Accepted)
- **날짜**: 2026-06-30

---

## 1. 맥락 (Context)
장례식장 DID 및 전용 키오스크 터미널 등 디지털 사이니지 장비를 24시간 안정적으로 구동해야 합니다. 
주요 기술적 제약조건 및 기능 요구사항은 다음과 같습니다:
1. **오프라인 동작 보장**: 인터넷이나 로컬 네트워크가 단절되어도 장례식 정보, 배경음악, 영정사진, 비디오 재생이 멈춤 없이 지속되어야 합니다.
2. **24시간 재생 및 저리소스 사용**: Chrome 기반의 웹 뷰(Electron 등)는 오랜 구동 시 메모리 누수가 빈번하며 저성능 셋톱박스에서 랙을 유발합니다.
3. **실시간 정보 갱신**: 백엔드에서 고인 정보 또는 장비 미디어 설정을 갱신하면 사이니지가 즉각 반영해야 합니다.

---

## 2. 결정 사항 (Decision)
위 제약사항을 극복하기 위해 다음과 같은 아키텍처 구조를 도입합니다:
1. **Flutter(Dart) 크로스 플랫폼 프레임워크 선택**:
   - 단일 코드베이스로 Android(셋톱박스) 및 Windows(미니 PC) 네이티브 기계어로 직접 컴파일 빌드하여 최고의 24시간 가동 안정성과 낮은 메모리 릭율을 유지합니다.
2. **실시간 신호 브로드캐스팅**:
   - .NET SignalR 허브(`DeviceHub`)를 신설하여 변경 이벤트를 실시간 중계합니다.
   - 플레이어는 변경 신호 수신 시, REST API를 통해 바뀐 메타데이터만 점진적으로 동기화(Pull)하는 가벼운 모델을 취합니다.
3. **오프라인 2계층 캐싱 아키텍처 구축**:
   - **데이터 캐시**: 경량 SQLite 데이터베이스(`sqflite`)를 로컬에 두어 장비 속성과 고인 DTO 정보를 저장 및 조회합니다.
   - **미디어 파일 캐시**: 비디오, 음악, 영정사진 바이너리는 최초 1회 디스크 로컬 스토리지에 보관하고 네트워크 다운 시 로컬 경로로 폴백(Fallback) 재생합니다.

---

## 3. 대안 검토 (Alternatives Considered)
1. **HTML5 + Electron (웹 뷰 방식)**:
   - 개발은 편리하지만, 메모리 점유율이 높고 장기 가동 시 미디어 디코딩으로 인한 시스템 셧다운 리스크가 커 배제했습니다.
2. **안드로이드 네이티브 (Kotlin/Java)**:
   - 특정 OS(안드로이드)에 강하게 결속되어, Windows 임베디드 사이니지를 사용하는 거래처 대응 시 유지보수 비용이 2배로 상승하므로 배제했습니다.

---

## 4. 결과 및 이점 (Consequences)
- **안정성 극대화**: 네트워크가 며칠 동안 끊기더라도 마지막으로 복제된 정보를 바탕으로 영정 화면이 100% 정상 구동됩니다.
- **실시간성 확보**: SignalR 소켓 연결로 운영자가 백엔드 대시보드에서 영상이나 음원을 바꾸는 즉시 플레이어에서 미디어가 끊김 없이 페이드인 재생됩니다.
- **하드웨어 유연성**: 임베디드 안드로이드 TV, Windows PC 등 하드웨어 사양에 맞춰 즉시 빌드 이식이 가능합니다.
