# 쪽지 — 받는 사람을 빠르게 고르고, 닿지 않으면 메일로 돌린다

상단 띠의 ✉ 가 어디서나 여는 쪽지 쓰기와, 그 쪽지가 **실제로 닿았는지**를
좇아 안 닿았으면 메일로 다시 보내는 길을 적는다 (2026-10-10).

## 1. 휴대폰에서는 창이 아니라 **화면을 채운다**

책상에서는 34rem 짜리 창이 맞다 — 보던 화면이 뒤에 남아 있어야 「무엇을 보다가
쓰려 했는지」가 지켜진다(`NoteWritePopup` 머리말). 그런데 **360px 짜리 화면에서
34rem 은 곧 화면 전체**이고, 거기에 `calc(100vw - 2rem)` 으로 테두리만 남기면
얻는 것 없이 셋을 잃는다.

- 가장자리 여백 때문에 받는 사람 딱지 줄이 한 줄 더 접힌다.
- 내용 칸이 여섯 줄로 고정되어, 자판이 올라오면 **보내기 단추가 그 아래로 숨는다.**
- 창의 최대 높이가 86vh 라 그 아래 띠만큼이 늘 빈다.

**가르는 값은 `Fill` 하나고 마크업은 하나다** — ⚡(빠른 지시)가 화면 크기 하나로
서랍과 화면을 가르는 것과 같은 수다. 값은 레이아웃이 내려 준다
(`MainLayout` → `HeaderTools.IsPhone`).

```
IsPhone ──▶ NoteWritePopup Fill=true ──▶ NoteWritePanel Fill=true
             · jsini-note-popup--full      · jsini-note--fill
             (창이 화면 네 변에 붙는다)      (내용 칸이 남은 높이를 먹고
                                              보내기 줄이 바닥에 붙는다)
```

### 창을 띄우는 **다른 자리는 그대로다**

`Fill` 을 주는 것은 상단 띠의 ✉ 하나뿐이다. 쪽지함의 「답장」과 위치 지도의 점은
안 준다 — 그쪽은 **뒤에 있는 목록이 보여야** 어느 쪽지에 답하는지, 누구를 눌렀는지
안다. 그래서 가르는 것을 미디어 질의가 아니라 클래스로 두었다.

### DevExpress 창의 속은 **재어 보고** 적었다

헤드리스 크롬 390×844 로 띄워 상자를 하나씩 쟀다. 눈대중으로는 못 맞춘다 —
높이를 채우는 사슬은 한 곳만 끊겨도 바닥값으로 주저앉는데, 그때도 화면은 멀쩡히
그려져서 코드만 읽어서는 안 보인다.

```
dxbl-popup-root > dxbl-popup-cell > dxbl-modal > dxbl-modal-root
  > dxbl-modal-dialog.dxbl-popup      ← CssClass 가 붙는 자리
      > div.dxbl-modal-content
          > dxbl-popup-header · div.dxbl-modal-body
```

| 걸린 자리 | 무엇이 문제였나 |
|---|---|
| `.dxbl-popup-root` | **그런 클래스가 없다.** 처음엔 이것을 겨누고 있었다 |
| 판의 `margin: 8px` · `max-width: 374px` · 내용 높이 | 셋을 다 풀어야 한다. 하나만 풀면 좌우만 붙거나 위아래만 붙는다 |
| `.dxbl-modal-content` 의 `max-height: 788px` | **인라인 스타일**이다(DevExpress 가 JS 로 잰다). 스타일시트에 규칙이 없어 CSS 만 뒤져서는 범인이 안 보인다 — `!important` 하나만 길이다 |
| 구르는 칸 | `.dxbl-popup-body` 가 아니라 **`.dxbl-modal-body`** 다 |
| 내용 칸이 안 늘어남 | 칸만 늘리면 편집기가 `Rows` 로 잡은 키(140px)를 그대로 쓴다. 이름이 `.dxbl-memo` 가 아니라 **`.dxbl-memo-edit`** 다 |
| tabler.css 의 `width: … !important` | ≤767px 에서 모든 창에 걸린다. 겨루려면 이쪽도 `!important` 이고, 그러면 **자릿수로 갈린다** — 저쪽이 (0,3,0)이라 클래스를 하나 더 붙여 (0,4,0) 으로 적는다 |

재어 본 결과 (390×844, DevExpress 26.1.4):

| | 전 | 후 |
|---|---|---|
| 창 | 374×697 (여백 8px · 모서리 8px) | **390×844** (네 변에 붙음) |
| 글 쓰는 칸 | 138px | **317px** |
| 보내기 줄 | 창 안에 떠 있음 | **바닥에 붙음**(sticky, y=763) |
| 몸통 스크롤 | 있음 | **없음**(내용 높이 = 칸 높이) |

## 2. 받는 사람을 **치지 않고** 고른다

여태 받는 사람을 정하는 길이 **치는 것 하나**였다. 두 글자부터 걸리니 적어도 두
번은 눌러야 하고, 휴대폰에서는 그 두 글자가 자판을 띄우고 한글을 조합하는 일이다.
그런데 쪽지를 쓰는 사람이 가장 자주 하는 일은 **어제 보낸 그 사람에게 또 보내는
것**이다.

`GET /api/notification/notes/recipients/quick`

| 담기는 것 | 무엇 |
|---|---|
| `recent` | **내 보낸함**에서 받는 사람별로 접어 가장 가까운 순 여덟. 딱지 한 번으로 담긴다 |
| `all` | 쪽지를 받을 수 있는 사람 전부(이름순). 「전체에서 고르기」로 편다 |
| `allTruncated` | 상한(200)에서 잘렸나 — 화면이 「더 있다」를 말한다 |

- **섞어 한 목록으로 두지 않는다.** 자주 쓰는 몇 사람이 낯선 이름 수십 개에 묻힌다.
- **최근도 지금 받을 수 있는 사람만 남긴다.** 그 사이에 기기를 지웠거나 푸시를 꺼서
  못 받게 된 사람이 딱지로 서 있으면, 눌러 담고 보내고 나서야 막힌 것을 안다.
- **나 자신은 전체 목록에서 뺀다.** 맨 앞에 서면 잘못 누르기 좋은 자리다. 손으로
  적으면 여전히 보낼 수 있다.
- **담긴 사람도 딱지 줄에 남는다** — 눌린 모습이 되고 한 번 더 누르면 빠진다.
  목록에서 지우면 여덟 개짜리 줄이 누를 때마다 흔들려 옆 사람을 잘못 누른다.
- **찾기와 전체 목록이 거르는 잣대가 같다**(`NoteRecipientResolver.ReachableAsync`
  한 메서드를 나눠 쓴다). 베껴 두면 한쪽만 고치는 날이 오고, 그러면 전체 목록에는
  있는 사람이 이름으로 치면 안 나온다.

### 고르고 나서도 목록이 닫히지 않는다

예전에는 찾은 사람을 하나 누르면 목록이 통째로 사라졌다. 「방금 고른 사람이 목록에
남아 한 번 더 누르게 된다」를 막으려던 것인데, 그 대신 **둘째 사람부터는 같은 글자를
다시 쳐야** 했다 — 한 부서에 셋을 보내는 일이 드물지 않다. 지금은 **담긴 사람만**
목록에서 빠진다.

손으로 친 글자를 Enter 로 담을 때는 전처럼 칸과 목록을 함께 비운다 — 그 글자가
딱지로 **옮겨 간** 것이라 찾던 결과도 뜻을 잃어서다.

### 보내기는 여전히 이 결과를 **믿지 않는다**

화면이 딱지에 담는 것은 사람이 적은 글자(또는 고른 아이디)이고, 서버가 보낼 때 그
글자에서 **다시 푼다.** 화면이 푼 아이디를 그대로 믿으면 브라우저에서 갈아 끼워
남의 이름으로 보낼 수 있다. 딱지에 이름이 적히는 것은 **보여 줄 때만**이고 보내는
값은 손대지 않는다.

## 3. **「보냈다」와 「닿았다」는 다르다** — 안 닿으면 메일로 돌린다

웹푸시는 우리가 푸시 서비스(FCM 등)에 넘기는 데까지만 우리 일이다. 기기가 꺼져
있으면 푸시 서비스가 **수명(TTL, 기본 6시간)까지 들고 있다가 조용히 버린다**
([docs/push-delivery.md](push-delivery.md)). 그래서 `notes.push_sent` 가 참이어도
받는 사람이 영영 모를 수 있는데, 보낸 쪽 화면에는 「앱 알림 1대」라고 적혀 있다.
**그 조용한 어긋남**을 메운다.

```
보낸다 ──▶ push_sent      우리가 푸시 서비스에 넘겼다
        ──▶ delivered_at  기기의 서비스워커가 받아서 되알려 줬다   ← 새 칸
        ──▶ read_at       사람이 쪽지를 열었다
        ──▶ fallback_email_at  두 시간이 지나도 안 닿아 메일로 돌렸다  ← 새 칸
```

### 도착 보고 — 서비스워커가 `POST /notes/delivered`

서비스워커에는 로그인 토큰이 없다(BFF — 이 포털의 토큰은 서버가 들고 있고 브라우저로
안 내려온다). 그래서 **쪽지 길 중 이 하나만 게이트웨이에서 익명**이고
(`notification-note-delivered-route`), 신원 대신 **쪽지 아이디(GUID)** 가 열쇠다.

- 할 수 있는 일이 「닿았다고 찍는 것」뿐이고 그 아이디는 보낸 사람과 받는 사람만
  아는 값이라, **새어도 잃는 것은 전환 메일 한 통**이다.
- **없는 아이디에도 참을 돌려준다.** 404 로 가르면 아이디를 하나씩 넣어 「있는 쪽지」를
  찾아볼 수 있게 된다.
- POST 로 못박고 분당 60회로 조인다(`push-ack`). 배포 알림(분당 3회)만큼 조이면
  **정상적인 보고가 거절되어 전환 메일이 헛되이 나간다.**
- 보고가 **실패해도 조용하다.** 그때 서버는 「안 닿았다」로 보아 메일을 보낸다 —
  쪽지가 전해지지 않는 쪽으로는 안 기운다.
- **시효가 지나 묶어 띄우는 경우에도 보고한다.** 안 그러면 며칠 만에 켠 기기가
  밀려 있던 쪽지를 다 받고도 서버는 「안 닿았다」로 보아 한 번 더 메일을 보낸다.

### 그래서 푸시를 **사람마다 따로** 보낸다

쪽지는 받는 사람마다 한 줄이라(`Note` 머리말) 페이로드에 실을 아이디도 사람마다
다르다. 한 번에 보내면 페이로드가 하나뿐이라 어느 쪽지가 닿았는지를 못 말하고,
그러면 전환 메일 판정이 통째로 서지 않는다.

값이 비싸지 않다 — 받는 사람이 서른을 넘지 않고(`MaxRecipients`) 어차피 기기마다
한 번씩 나가던 길이다. 늘어나는 것은 발송 기록의 묶음 수뿐인데, 알림함은 사람별로
보므로 달라 보이지 않는다.

### 전환 메일 배치 (`NoteFallbackMailer`)

5분마다 깨어나 **때가 된 쪽지**를 집어 메일로 돌린다.

| 거르는 조건 | 왜 |
|---|---|
| `delivered_at IS NULL` | **닿았는데 안 읽은 것은 건드리지 않는다** — 알림은 멀쩡히 받고 나중에 보려고 둔 사람에게 메일을 한 통 더 보내는 것은 도움이 아니라 소음이다 |
| `read_at IS NULL` | 어딘가에서 이미 열어 봤으면 전해진 것이다 |
| `email_sent = false` | 「쪽지 메일받기」를 켠 사람에게는 보낼 때 이미 갔다 |
| `fallback_email_at IS NULL` | 이 칸이 없으면 5분마다 같은 메일이 나간다 |
| `sent_at <= now - 2시간` | `NoteFallbackMail:AfterMinutes` |
| `sent_at >= now - 72시간` | `LookbackHours` — 배치를 며칠 멈췄다 켜는 날 그동안 쌓인 것이 한꺼번에 나가는 것을 막는 안전장치 |

- **「쪽지 메일받기」는 보지 않는다.** 그것을 켠 사람에게는 보낼 때 이미 나갔으므로,
  여기까지 내려온 사람은 전부 안 켠 사람이다. 대신 **전체 메일 스위치**
  (`email_enabled`, 행이 없으면 켜짐)는 지킨다 — 그것을 끈 사람은 「메일로는 연락하지
  말라」고 말한 것이라 전환 발송이라고 넘어설 수 있는 뜻이 아니다. 그런 줄에는
  **자국을 찍어 다시 안 집는다**(고쳐질 일이 아니다).
- **주소가 없는 줄에는 자국을 안 찍는다.** 언젠가 등록되면 풀릴 일이라 되돌아볼
  창(72시간)이 닫히면 저절로 빠진다. 대신 까닭을 `notify_note` 에 적어 둔다.
- **보내다 실패해도 자국을 안 찍는다.** SMTP 가 잠깐 막힌 것과 「보낼 수 없는 사람」은
  다르다 — 다음 차례에 다시 해 본다.
- 한 바퀴에 50통까지. 남은 것은 다음 차례가 집는다 — **떨어뜨리지 않는다.**
- `NoteFallbackMail:Enabled=false` 로 아예 끌 수 있다. 메일이 나가는 길은 한 번 잘못
  열리면 수십 통이 되돌릴 수 없이 나간다.

메일 본문에는 **「왜 메일로 왔는지」를 한 줄 얹는다.** 그 줄이 없으면 받는 사람은
같은 글을 두 번 받았다고 여긴다(앱 알림이 늦게라도 뜰 수 있다). 쪽지함 주소를 함께
적는 것은 답장하는 길이 거기뿐이기 때문이다 — 이 메일에 회신해 봐야 발송 계정으로
갈 뿐이다. 주소의 앞머리는 `Portal:BaseUrl` 이고, **비면 링크 줄을 통째로 뺀다**
(localhost 주소가 적힌 메일은 아무도 못 연다).

### 보낸 사람이 보는 자리 — 쪽지함의 「전달」 칸

| 딱지 | 뜻 |
|---|---|
| 기기 도착 | `delivered_at` 이 찍혔다. 상대의 기기가 실제로 받았다 |
| 메일 전환 | 푸시가 안 닿아 배치가 메일로 돌렸다 — 전해지기는 했지만 원래 길이 막혔다 |
| 보냄 | 푸시 서비스에 넘겼다. 기기가 받았다는 신호는 **아직 없다** |
| (빈칸) | 푸시 대상이 아니었다(메일로만 받는 사람) |

## 어디를 보면 되나

```sql
-- 닿았나 · 메일로 돌았나
select sent_at, sender_key, receiver_key, push_sent, delivered_at, fallback_email_at, read_at, notify_note
  from scom.notes order by sent_at desc limit 30;

-- 지금 전환 메일을 기다리는 줄 (부분 색인 IX_notes_fallback 이 그대로 이 모양이다)
select count(*) from scom.notes
 where read_at is null and delivered_at is null and fallback_email_at is null
   and not email_sent and not receiver_deleted and not is_deleted;
```

배치 로그는 `쪽지 전환 메일 N통. 대상=… 주소없음=… 메일꺼둠=…` 한 줄이다.

## 설정

| 열쇠 | 기본 | 무엇 |
|---|---|---|
| `NoteFallbackMail:Enabled` | `true` | 끄면 배치가 아예 안 깨어난다 |
| `NoteFallbackMail:AfterMinutes` | `120` | 안 닿은 채 이만큼 지나면 메일로 |
| `NoteFallbackMail:LookbackHours` | `72` | 이보다 오래된 쪽지는 건드리지 않는다 |
| `NoteFallbackMail:IntervalMinutes` | `5` | 훑는 간격 |
| `NoteFallbackMail:MaxPerRun` | `50` | 한 바퀴 상한 |
